# ADR 0017: 대규모 일괄 배정과 구역 담당자 셀프 배정

- 상태: Accepted
- 날짜: 2026-08-29
- 대체 범위: ADR 0009의 `일반 영업 직원 호출 불가`, `배정·복사 최대 50개` 결정

## 배경

운영 대상 학교가 300곳을 넘으므로 학교를 하나씩 선택하고 저장하는 관리자 흐름은 실제 월 배정에 사용할 수 없다. 또한 관리자가 모든 학교를 미리 나누지 못한 경우에도 구역 담당 직원이 자기 구역의 미배정 학교를 빠르게 가져갈 수 있어야 한다. 다만 Client가 임의의 구역을 주장하거나 동시에 같은 학교를 가져가 중복 배정되는 상황은 허용할 수 없다.

## 결정

- 관리자와 영업 직원이 공통으로 사용하는 체크박스 기반 학교 선택기를 둔다. 학교명·주소 검색, 자치구·학교급 필터, 검색 결과 전체 선택, 필터 변경 후에도 유지되는 선택 바구니, 선택 수·자치구별 요약과 고정 실행 영역을 제공한다.
- `<select multiple>`은 사용하지 않는다. 각 학교는 실제 Checkbox와 Label로 조작하며 전체 선택은 전부·일부·없음 상태를 표현한다.
- 관리자는 선택한 모든 학교에 구역과 주 담당자를 한 번에 지정한다. 한 요청은 전부 성공하거나 전부 실패한다.
- 영업 직원의 셀프 배정은 현재 `active` Cycle에서만 허용한다. 서버는 해당 Cycle에 이미 존재하는 배정 중 로그인 직원이 `assigneeIds`에 포함된 구역만 ‘담당 구역’으로 인정한다. Client가 보낸 `zoneId`는 이 관계와 다시 대조한다.
- 새 Cycle을 전월에서 복사하면 기존 담당 구역 관계가 유지되어 직원이 즉시 셀프 배정할 수 있다. 완전히 빈 Cycle은 관리자가 직원에게 학교 한 곳을 최초 배정해 구역 관계를 만든 뒤 셀프 배정을 허용한다.
- 미배정 학교만 생성할 수 있다. Transaction이 Cycle의 현재 배정 문서를 읽고 대상 학교가 이미 존재하는지 확인한 뒤 생성하므로 동시 요청에서 한 요청만 성공한다. 충돌한 Client는 최신 Workspace를 다시 읽는다.
- 배정 생성과 셀프 배정은 Request ID·Payload 지문으로 멱등 처리하고, `SALES_ASSIGNMENTS_CREATED` 또는 `SALES_ASSIGNMENTS_CLAIMED` Audit Log와 같은 Transaction에서 기록한다.
- 한 Cycle과 한 요청의 상한은 400개 학교다. Firestore Transaction의 500 Write 한도에서 배정 문서 외 Cycle·설정·Audit·Request Lock 쓰기를 위한 여유를 남긴다.
- 월 방문 집계와 전월 복사도 같은 400개 상한을 사용한다. 범위를 초과한 상태를 조용히 일부 집계하지 않고 명시적으로 거부한다.

## 결과

- 300곳 이상을 검색·필터·전체 선택으로 수 분 내 배정할 수 있고, 필터를 바꿔도 누적 선택이 사라지지 않는다.
- 관리자가 초기 구역 관계만 설정하면 현장 담당자가 같은 구역의 미배정 학교를 모바일에서 직접 여러 곳 가져올 수 있다.
- 직원은 다른 직원의 구역을 선택할 수 없고, 과거 월이나 Draft Cycle에는 셀프 배정할 수 없다.
- 동시 선택과 네트워크 재시도에도 중복 학교, 부분 성공, 중복 Audit가 생기지 않는다.
