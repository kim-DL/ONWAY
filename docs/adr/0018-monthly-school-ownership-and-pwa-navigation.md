# ADR 0018: 월별 학교 소유권과 PWA 내비게이션

- 상태: Accepted
- 날짜: 2026-08-29
- 대체 범위: ADR 0017의 `구역 기반 셀프 배정` 권한 모델

## 배경

구역과 학교를 모두 필수 배정 단위로 사용하면 관리자가 `구역 → 직원 → 학교`를 반복 선택해야 하고, 직원이 학교를 직접 가져오려면 관리자가 먼저 같은 구역의 학교 한 곳을 배정해야 했다. 실제 운영은 매월 담당 학교 목록을 유지·조정하는 방식이며, 구역은 행정·집계용 분류에 가깝다.

또한 직원 PWA는 탭, 학교 상세, 검색, 바텀시트를 React 로컬 상태로만 전환해 Android 시스템 뒤로가기가 이전 화면을 복원하지 못했다. 관리자 Google 로그인은 토큰 갱신 알림의 순서에 의존해 활성화가 끝난 뒤에도 로딩 화면에 남을 수 있었다.

## 결정

1. 운영의 단일 원본은 `salesCycles/{cycleId}/assignments/{schoolId}`의 월별 직원-학교 배정이다.
2. 새 월은 이전 Cycle의 학교·담당자를 복사하고, 관리자가 다중 추가·미착수 배정 제외·담당 변경으로 조정한다.
3. `zoneId`는 기존 감사·CSV 호환을 위한 nullable 분류 태그다. 신규 직접 배정은 `null`로 저장하며 권한 경계로 사용하지 않는다.
4. 활성 영업 직원은 현재 Cycle의 미배정 학교를 다중 선택해 직접 가져올 수 있다. 동시 선택은 Firestore transaction의 create 충돌로 한 명만 성공한다.
5. 직원은 자신이 단독 담당하고 아직 월간 업무 기록이 없는 학교만 다중 제외할 수 있다. 방문, 홍보지, 샘플, 후속 상태가 생긴 학교는 제외하지 않고 관리자 재배정으로 처리한다.
6. 관리자는 종료되지 않은 Cycle의 미착수 배정을 다중 제외할 수 있다. 모든 변경은 request lock과 audit log를 남기며 통계를 같은 transaction에서 다시 계산한다.
7. PWA의 탭, 검색, 학교 상세, 바텀시트는 History API 항목을 생성하고 `popstate`로 복원한다. 시스템 뒤로가기는 가장 가까운 앱 화면을 먼저 닫거나 복원한다.
8. Google 관리자 활성화 직후 갱신된 ID token과 서버 authz 문서를 직접 검증해 인증 상태를 확정한다. 백그라운드 토큰 갱신은 이미 표시 중인 업무 화면을 로딩 화면으로 되돌리지 않는다.

## UX 원칙

- 300개 이상 학교는 checkbox, 필터, 검색, 선택 유지, 선택 후 나타나는 batch action을 사용한다.
- 직원 화면의 기본 범위는 `내 학교`, 보조 범위는 `팀 전체`다.
- 구역 대신 학교의 행정구를 검색·필터 정보로 보여준다.
- `활동`은 CSV 내보내기가 아니라 방문 전, 후속·재방문, 완료의 실행 큐다.
- 모바일 하단 메뉴는 관리자 화면과 같은 짙은 녹색 고정 dock, 라임 활성 상태, 44px 이상 터치 영역을 사용한다.

## 결과

- 관리자는 담당자를 한 번 선택하고 수백 개 학교를 일괄 배정하거나 미착수 배정을 정리할 수 있다.
- 직원은 관리자 선행 구역 배정 없이 담당 학교를 직접 구성할 수 있다.
- 업무 이력이 있는 학교의 감사 연속성은 유지된다.
- 기존 zone 데이터와 CSV는 파괴적 migration 없이 계속 읽을 수 있다.
- 설치형 PWA의 뒤로가기와 관리자 로그인 전환이 브라우저·Firebase의 공식 상태 모델과 일치한다.
