# 2026-10-30 시작 경로·검색·사용하지 않는 UI 코드 최적화

기준 소스는 `24c462ad1d6797afdf832d64de60febfec1459d6`이다. 사용자가 요청한 앱 경량화와 정리를 진행하며, 승인된 유리 버튼·로그인 배치·업무 기능은 유지했다. 최종 main/Hosting 상태는 릴리스 기록과 HANDOFF에서 확인한다.

## 변경

- 시작 페이지는 Tailwind 기반 스타일·공통 기본값·PWA·인증 스타일만 받는다. 기존 업무 스타일은 `workspace.css`로 묶어 이미 지연 로딩하던 인증 후 AppShell과 함께 받는다. 업무 CSS의 기존 상대 순서는 유지한다. 인증 버튼·PIN 간격 규칙은 인증 파일로 옮겨 여러 파일에서 덮어쓰던 선언을 합쳤다.
- Tailwind 탐색 기준을 `src`로 한정했다. 문서·스크립트·Functions·테스트 산출물 폴더를 감시하지 않는지 검사한다. [공식 source 경로 지정 방식](https://tailwindcss.com/docs/detecting-classes-in-source-files)을 사용하며 라이브러리·폰트·영상은 추가하지 않았다.
- 실제 사용 지점이 없는 `OnnuriLoader` 별칭, `SkeletonCard`, 옛 재고 목록 썸네일과 전용 테스트·mock을 제거했다. 로딩의 실제 구현과 검사는 `LoadingIndicator`/`loading-primitives.test.ts`로 유지했다. 옛 `data-onnuri-loader` 별칭, 사용하지 않는 모드 라벨·스켈레톤·대기 레이아웃 CSS도 정리했다. 문자열 검사만으로 동적 클래스나 Next 특수 진입점을 삭제하지 않았다.
- 검색 인덱스 생성 시 별칭의 Unicode 문자 배열을 준비하고, 검색어 분해·초성 판정·오타 허용 거리를 검색당 한 번 계산한다. 편집 거리 계산은 두 행을 재사용하며 한국어 정렬기 객체도 재사용한다. 점수·정렬·오타 기준은 동일하다. 직원 데이터는 기존 인덱스 수명 안에만 남으며 별도의 전역 데이터 캐시는 만들지 않았다.
- 모바일 바깥 배경을 시작 화면/PWA와 같은 `#F8FAFC`로 맞춰 빈 화면과 스크롤 경계의 크림색 비침을 없앴다. 유리 버튼의 중복 선언을 제거했다. 로고·3/4개 권한 버튼·44px 누름 영역·환영 모션·본문 업무색은 유지한다.
- 기존 용량 예산을 유지하고 최초 HTML CSS에 raw 32KiB/gzip 8KiB 상한과 업무 CSS 지연 로딩 검사를 추가했다. 구성 요소 시험은 분리한 두 CSS 진입점을 함께 읽도록 조정했다. 오래된 로딩 측정기의 모드 선택 조작만 현재 상시 버튼에 맞췄다.

## 동일 조건 전후 측정

최초 HTML의 CSS는 **196,309→22,819B raw**, **37,102→6,436B gzip**으로 압축 기준 약 **82.7%** 줄었다. 업무 CSS 자체를 버리는 대신 필요한 시점으로 옮긴 효과다. 전체 CSS gzip은 78,275→78,208B, 공통/기존 업무 CSS gzip은 44,387→44,320B다. 초기 JS gzip은 143,643→143,657B(+14B)로, CSS 청크 연결 정보의 작은 증가를 포함해 모든 기존 예산을 통과했다.

합성 데이터와 실제 에뮬레이터 인증을 사용한 정적 내보내기를 비교했다. Chromium 151, 390×844, CPU 4배 제한, 지연 120ms, 다운로드 200,000B/s이며 각 경로 1회 준비 후 5회를 측정했다. 서비스 워커를 막고 로컬 호스트만 허용하는 요청 가로채기로 HTTP 캐시를 끈 조건이다. 반복 진입도 HTTP 캐시가 따뜻한 조건이라는 뜻은 아니다. 서버 코드·Rules는 기준 소스와 같으며 두 빌드에 같은 에뮬레이터를 적용했다.

5,000개 합성 학교의 정확·오타·초성·별칭 등 155개 검색 표본을 같은 Node 프로세스에서 실행 순서를 번갈아 비교했다. 결과·점수·정렬은 모두 일치했다. 중앙값 **18.64→15.41ms**, p95 **24.70→21.27ms**다. 한 번의 인덱스 생성 중앙값은 **149.56→155.66ms**로 약 6ms 늘었다. 입력 때 반복하던 문자 배열 준비를 생성 시점으로 옮긴 비용이다. 다른 검사와 겹친 최초 진단 측정값은 최종 수치에 사용하지 않았다.

## 보존 범위와 검증 자료

정적 내보내기, 기존 지연 로딩, 오프라인/PWA 보관 정책, 인증·권한 회수·Callable·App Check·revision·request ID·감사 이력·서버 확인 후 저장 완료 계약을 보존한다. Functions/Rules/Auth와 운영 업무 데이터에 대한 쓰기는 없다.

ignored `output/app-optimization-20261030/`에 import/CSS 감사, 전후 빌드 용량, 검색 일치와 표본, PIN 전후 320/360/390/1280px PNG·기하 비교, 로컬 검사 로그를 보관한다. 개별 시작 전환 표본·PIN/업무 PNG는 `output/loading-experience-20261029/opt-before/`와 `opt-after/`에 있다. Aside의 360×780 직접 화면 확인과 S26 규격 DPR 3 자동 검사는 실제 S26 하드웨어 인수와 구분한다.

비교용 HTTP 서버의 Windows 절대 경로 연결 실패는 상대 경로로 수정해 해결했다. 기준 worktree에 의존성이 없어 발생한 Functions 컴파일 실패는 전후 서버 코드가 같음을 확인한 뒤 설치된 주 작업 트리의 같은 Functions를 두 측정에 사용해 해결했다. 운영 앱·검사 기준·timeout을 바꾸지 않았다. Next dev가 자동 생성한 AGENTS 안내 제목 수준 변경도 함께 기록하며 전역 지침은 수정하지 않는다.

첫 일반 브라우저 검사는 **350 PASS / 플랫폼 조건 4 SKIP / 2 FAIL**이었다. 실패는 재고 키보드 초점의 즉시 CSS 조회(`-3px` 기대/`0px` 관측)와 모션 정지 직후 transform 비교(최대 약 0.0002px 차이)다. 소스를 바꾸지 않은 모바일·데스크톱 각 3회, 합계 **12회 재현 검사 PASS**를 먼저 확인했다. 초점은 [Playwright의 `toHaveCSS`](https://playwright.dev/docs/api/class-locatorassertions#locator-assertions-to-have-css)로 표시 상태를 기다리고, 모션은 [Animation.ready](https://developer.mozilla.org/en-US/docs/Web/API/Animation/ready)의 정지 처리 완료 후 기존 350ms 동안 정확히 같은 transform인지 검사하도록 보강했다. 판정값·테스트 timeout·skip·CI retry는 유지했으며, 보강 후 같은 **12회 검사 PASS**다. 앱의 모션이나 초점 동작은 변경하지 않았다.
