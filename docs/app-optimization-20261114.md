# 급식길 비동기 오류·PWA 다운로드 최적화

## 범위와 기준

시작 소스는 `51ee23f`, 운영 앱 소스는 `a4b86e2`다. 기존 운영 산출물 143개의 SHA-256이 보존된 후보 목록과 모두 일치함을 확인했다. 별도 `codex/app-optimization-20261114` 브랜치에서 작업했다. 다른 worktree와 운영 데이터는 변경하지 않는다.

점검은 앱 진입·읽기 요청, 비동기 상태와 캐시, 정적·동적 import 및 CSS 사용처로 나눴다. 부모와 두 독립 감사가 발견한 문제를 재현한 뒤 최소 수정했다. Poteto의 Model the Domain에 따라 기존 사진 식별자와 요청 수명을 사용하며, Laziness Protocol에 따라 공통 비동기 프레임워크를 추가하지 않았다.

## 확인한 문제와 수정

### 사진 확대 시 폐기된 URL 재사용

학교 사진의 원본은 확대할 때 활성화된다. 축소할 때 URL을 폐기하지만 ready 상태는 남아 있어 다시 확대하면 폐기한 주소를 재사용했다. 세션이 달라져도 같은 학교·버전 키가 맞으면 이전 URL을 반환했다.

기존 세션 namespace를 UI 요청 키에도 포함하고 cleanup에서 해당 키의 상태를 지운다. 사진 설명만 바뀌거나 같은 버전이 새 객체로 전달되는 경우에는 재조회하지 않도록 학교·슬롯·버전 식별자로 effect 수명을 정했다. 사진 저장소·인증·캐시 정책은 유지한다.

### 방문 이력 새로고침 뒤 이전 페이지가 섞이는 오류

이전 기록을 읽는 도중 방문 저장으로 첫 페이지를 새로고침하면, 늦게 온 이전 응답이 새 목록에 섞이고 커서와 마지막 페이지 여부를 덮었다. 늦은 실패도 새 화면에 오류를 표시할 수 있었다. 같은 이벤트 안에서 더 보기를 두 번 호출하면 요청 두 개가 나갔다.

첫 페이지와 더 보기가 요청 수명을 공유하게 했다. 폐기된 요청의 성공·실패를 무시하고, 현재 요청은 동기 잠금으로 중복 호출을 막는다. 정상 오류는 기존 재시도 경로를 유지한다. 정렬·페이지 합치기·Callable·서버 저장 계약은 바꾸지 않았다.

### 학교 아이콘의 오프라인 누락

학교 홈·검색에서 사용하는 `school-ceramic-building-v1.webp`가 사전 캐시와 공개 자산 목록에 빠져 있었다. 기존 실제 서비스 워커를 로컬 Chromium에 설치하고 HTTP 캐시를 지운 뒤 오프라인으로 바꾸자 거래처 돋보기는 200, 학교 아이콘은 연결 오류로 실패했다.

학교 아이콘을 명시적 공개 자산·사전 캐시·빌드 검사에 포함했다. 비공개 사진과 API 응답의 캐시 범위는 넓히지 않았다.

### 같은 이미지의 중복 다운로드와 업데이트 재다운로드

영업의 찾기·추가·정리 아이콘은 거래처 원본과 파일 해시가 같다. CSS에서 원본 경로를 공유하고 중복 사전 캐시 세 항목을 제거했다. 기존 공개 URL 세 개는 이미 열린 이전 PWA를 위해 파일로 보존한다. 새 화면은 해당 주소를 사용하지 않는다.

정적 공개 파일의 revision이 매 빌드 UUID 또는 커밋이어서 내용이 같아도 다시 받았다. 실제 파일의 SHA-256으로 revision을 만들고, HTML과 생성 manifest는 기존 빌드 revision을 유지한다. Hosting 검사도 정적 파일 revision과 실제 바이트의 해시 일치를 검사한다. 사용자의 업데이트 승인 정책은 유지한다.

### 폐기 스타일과 삭제하지 않은 코드

체크박스의 옛 숨김 속성 여섯 개는 바로 뒤의 같은 선택자가 모두 덮었다. 실제 사용하는 `position: absolute`는 남기고 중복 블록을 제거했다. import graph에서 미도달로 나온 다섯 모듈은 Next 특수 진입점이나 seed·검색 출판·pilot CLI/테스트가 사용하므로 삭제하지 않았다. 동적 semantic CSS도 실제 사용을 확인했다.

## 검증 이력

전체 단위 기준 검사는 2,059개 통과·23개 조건부 skip·1개 시간 초과였다. 시간 초과는 기존 Functions 런타임 신원 모듈 import 검사였고 해당 파일만 재실행해 4개가 모두 통과했다. timeout이나 기대값을 완화하지 않았다. 이를 전체 첫 실행 성공으로 합산하지 않는다.

두 hook의 기존 소스에서 실제 React 브라우저 5개가 모두 실패하며 문제를 재현했다. 수정 후 모바일·데스크톱 10개가 모두 통과했다. 관련 단위 15개와 주변 계약·PWA 단위 31개도 통과했다. 전역 lint, 변경 파일 lint, Functions 타입 검사가 통과했다. 새 브라우저 10개는 일반 화면 회귀에서 제외하여 같은 검사를 반복하지 않는다.

일반 화면 회귀는 562개 통과·4개 조건부 skip·6개 실패였다. 실패는 이전 코럴 배경과 파란 초점색을 기대하던 세 검사 × 두 브라우저였다. 승인된 새벽하늘·펄 배경과 라일락 초점에 맞췄으며, 접근성·44px·목록 정보·고대비·레이아웃 검사는 유지했다. 보정 첫 실행은 2개 통과·4개 실패였다. 브라우저가 생략하는 기본 그라디언트 각도와 alpha 0인 투명색의 검정 채널을 잘못 비교한 검사 문제를 고쳐 남은 4개가 통과했다. 최종 일반 화면 568개와 별도 신규 10개 통과를 확인했으며 전체 회귀는 반복하지 않았다.

첫 운영 빌드는 번들 생성 후 새 브라우저 fixture의 Window 타입이 spec에 포함되지 않아 타입 검사에서 실패했다. type-only import로 연결하고 앱 TypeScript와 해당 lint를 통과했다. 런타임 코드·timeout·검사 제외 설정은 바꾸지 않았다.

최종 `npm run build:hosting`과 성능·PWA·Hosting gate는 모두 통과했다. 산출물은 143개, 사전 캐시는 127개다. 기존 용량 한도·보안 정책·조건부 skip을 변경하지 않았다. 사용자 요청에 따라 같은 전체 검증을 원격 CI에서 반복하지 않았으며, 최종 커밋의 원격 CI 성공으로 보고하지 않는다.

의존성 audit은 high/critical 0, moderate 38, low 1이다. 이번에는 패키지나 lock을 변경하지 않았다. Functions·Firebase 설정·Rules·패키지/lock의 Git 차이도 없다.

## 성능 측정 범위

파일 바이트와 실제 요청 개수로 비교한다. 운영 사용자 지연 시간이나 Core Web Vitals 개선률은 측정하지 않았다. 사전 캐시하는 공개 정적 파일은 19개·590,446B에서 중복 제거와 누락 아이콘 추가를 합쳐 17개·574,426B로 줄었다. 중복 파일 25,286B를 제외하고 학교 아이콘 9,266B를 추가해 순감소는 16,020B다. 처음 UUID에서 내용 해시로 전환할 때는 한 번 다시 받고, 이후 같은 파일을 유지하는 업데이트부터 캐시를 재사용한다.

최종 생성 서비스 워커의 정적 revision이 실제 파일 해시인지 검사한 뒤, 공개 revision과 셸 revision만 바꾸는 3세대 합성 업데이트를 실행했다. 최초 정적 파일 17요청, 내용이 같은 다음 세대 0요청, SVG 하나만 바꾼 세대 해당 파일 1요청이었다. 외부 요청은 0, 변경 SVG는 오프라인에서 새 내용과 일치했다. HTML·manifest·변경된 앱 코드의 다운로드가 없어졌다는 뜻은 아니다.

별도로 수정하지 않은 최종 `out/sw.js`를 로컬 Chromium에 설치하고 HTTP 캐시를 비활성화한 뒤 오프라인으로 전환했다. 학교·거래처·영업 아이콘 다섯 개가 모두 서비스 워커에서 200으로 응답하고 파일 해시도 일치했다. 외부 요청은 0이었다.

최초 JavaScript 크기는 같고 전체 CSS 압축 결과는 4B 늘었다. 이번 성능 개선은 사진 재조회·중복 페이지 요청과 정적 파일 재다운로드를 줄이는 데 있다.
