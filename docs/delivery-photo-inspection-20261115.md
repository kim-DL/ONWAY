# 납품사진 라벨 확대 개선

저장된 납품사진에서 상자 라벨과 제품 정보를 충분히 크게 읽도록 기하·조작부·프레임을 개선했다. 기준은 main `5a0e274`, 작업 브랜치는 `codex/delivery-photo-inspection`이다. 11월14일에 시작해15일에 로컬 검증을 마쳤다. 커밋·병합·운영 배포는 이번 요청 범위에 포함하지 않는다.

이 문서는 첫 로컬 개편 기록이다. 이후 사용자가 모바일250%와 수신 대기를 다시 보고해 저장 픽셀800%·변환/조회 대기 개선을 적용했다. 현재 변경과 검증은 [후속 확대·조회 기록](delivery-photo-loading-20261115.md)을 기준으로 한다.

## 확인한 제약과 원인

조회는 이미 썸네일이 아닌 인증된 evidence를 사용한다. 저장 사진의 긴 변은 최대2560px이며 전송 WebP 품질0.9, 서버 evidence 품질88 계약은 유지한다. 기존 사진에서 없어진 세부 정보를 확대만으로 복구할 수는 없다.

공통 기하가 화면 맞춤 대비 최대 배율을2.5 또는3으로 제한했다. 높은 DPR에서는2.5로 더 낮췄다. Aside에서 실제 저장 뷰어와 합성2400×1800 사진으로 재현한 결과,390×844/DPR1에서 최대3배, 실제 렌더 너비1068px으로 원본 너비2400px에 못 미쳤다. 자동화의 DPR2.625 모바일에서도2.5배 상한을 확인했다.

숫자는 화면 맞춤을100%로 표시했으므로 저장된 픽셀 크기와 구분하기 어려웠다. 높이60dvh/620px, 데스크톱 시트860px 제한과 큰 헤더·중복 닫기도 사진 공간을 줄였다. overflow를 푸는 대신 프레임 공간과 이동 경계를 함께 유지해야 한다.

확대 중 축소 버튼에 포커스를 두고 오른쪽 방향키를 누르면1/2에서2/2로 바뀌는 오류도 Aside에서 직접 재현했다. stage의 pan 처리와 별도로 바깥 viewer가 방향키를 사진 전환으로 처리했다.

## 적용한 동작

기존 `PhotoView {scale,x,y}`와 `PhotoGeometry`를 사용하고 기하에 `nativeScale`을 추가했다. fit은 `min(1,w/nw,h/nh)`, nativeScale은 `1/fit`, 최대는 `max(8,2*nativeScale)`이다. 화면 맞춤8배와 저장 픽셀200% 중 큰 쪽까지 허용한다. DPR로 CSS 표시 크기의 상한을 낮추지 않는다. 작은 사진은 처음부터 늘리지 않는다. 이 한도는 조작 정책이며 현장 판독 임계값을 측정한 결과는 아니다.

배율은 저장된 사진을 기준으로 계산한다. `원본 크기`는 저장 이미지1픽셀을 CSS1픽셀로 표시하며100%가 된다. `화면 맞춤`은 전체 사진을 보여준다. 기존1.8배 버튼을 원본 크기로 교체하고 네 개 버튼을 유지했다. 더블탭·더블클릭의1.8배/맞춤 토글은 유지한다. 안내와 조작부는 기본14px의 rem 단위를 사용하며44px 터치 영역과 좁은 화면 줄바꿈을 유지한다.

기하와 gesture 엔진 하나가 scale·pan·상한·포인터·프레임을 계속 소유한다. React에는 배율과 버튼 상태만 투영한다. resize는 확대 중 원본 좌표의 중심과 실제 표시 크기를 보존한 뒤 새 경계에 제한한다. 화면 맞춤 상태는 새 화면에 맞춘다.

저장 납품사진은8px 여백 안에서 가용 화면의 폭과 높이를 사용한다. 1280px 상한도 없앴다. 기존 wrapper의 지역 클래스와 직접 자식에 한정한 CSS 중첩으로 자신의 dialog·header·body·footer만 지정한다. 중첩 삭제 확인과 재고·촬영 미리보기의 프레임은 바꾸지 않는다. 긴 제목은 전체 텍스트와 접근성 이름을 유지하면서 화면에서 두 줄로 제한한다. 닫기는 헤더에 유지하고 하단 중복 닫기를 없앴다.

확대 중 방향키·드래그는 사진 이동이며, fit일 때만 stage의 좌우키·swipe로 사진을 넘긴다. 명시적 이전·다음은 유지하고 새 사진은 fit으로 시작한다. `BottomSheet`와 `usePhotoMorph`의 닫기·Back·초점·스크롤 및 private Blob의 세션·교체·취소·해제 소유권을 유지한다. 업로드·outbox·인증·권한·request ID·revision·보관 기한·서버 확인 후 완료·삭제 서버 처리는 변경하지 않는다.

`poteto-mode`의 Model the Domain으로 기하와 제스처 소유권을 유지했다. Laziness Protocol로 새 전체화면 상태·시트 props·별도 이미지 없이 기존 경계를 고쳤다. Prove It Works에 따라 표시 숫자와 실제 렌더 크기를 함께 확인했다. `unslop-ui`로 작은 안내와 중복 버튼을 정리했다. 원 저작자는 [@heydamir](https://x.com/heydamir)이며 라이선스는 CC BY4.0이다. 두 독립 같은 모델 후보와 별도 판정·최종 검토를 사용했으며 모델 다양성은 없다.

## 검증과 실패 이력

관련 단위30개가 통과했다. Chromium PC16개·모바일16개와 WebKit8개의 고유 브라우저40개가 최종 통과했다. 입력 장치별로 분리한 Chromium4개는 해당하지 않는 프로젝트에서 제외했다. 전체 CI·전체 회귀·백엔드 에뮬레이터는 실행하지 않았다. 바뀐 재고 인증 흐름 테스트의 옛 버튼/배율 기대값은 갱신했지만 그 긴 업무 흐름을 재실행했다고 세지 않는다.

확대 수치만 확인하지 않았다. 저장 크기에서2400×1800의 실제 렌더가2400×1800인지, 최대 확대 시 data-scale과 렌더 비율이 맞는지, 모든 가장자리까지 이동하는지 확인했다. 모바일 DPR2.625에서 같은2400px 사진을 실제4800px 너비까지 표시했다. 휠·핀치·남은 한 손가락 이동·더블탭·취소·키보드·창 크기 변경·사진 전환·오류 재시도·Blob 해제·초점 복원·Back을 확인했다. 삭제는 합성 I/O로 실패·busy 닫기 차단·취소를 확인했으며 실제 삭제는 없다.

390px에서 사진 프레임은 기존356×506.39에서356×569.53px로 늘었다. 1280px 화면에서는818×432에서1246×465.53px로 늘었고,1920px 화면에서는1886×825.53px를 사용한다. 320px/200% 글자와740×360의 짧은 화면에서 닫기·확대·맞춤에 도달함을 확인했다. 합성 WebP 라벨의 제품명·중량·기한·제조번호 화면도 직접 확인했다.

처음의 확대 재현은 `Expected: >= 8 / Received: 3`과 모바일 `Received: 2.5`로 실패했다. 구현 후에는 각각8배 및 약12.698배에서 실제 렌더와 일치했다. 초기 프레임 검사는 선택한8px 여백을0px로 가정해 실패했으며 기대값을 실제 선택 설계에 맞췄다. WebKit의 최초 비율 검사는 초기 img 너비의 CSS 전환이 끝나기 전에 기준 너비를 읽어 실패했다. 렌더가 fit에 도달함을 먼저 기다리도록 수정했고 통과했다. reduced-motion의0.01ms 공통 전환이 한 paint 동안 이전 computed transform을 보여 주는 현상도 같은 방식으로 구분했다. 이 관측을 앱의 영구적인 배율 오류로 보고하지 않는다.

독립 검토가 제기한120자 거래처명/200% 위험은 실제 헤더733.75px로 재현됐다. 두 줄 제목 제한 후 Chromium과 WebKit의 해당 검사가 통과했다. 첫 운영 빌드의 history/viewer CSS6942B는 기존5632B 한도를 넘었다. 지역 wrapper와 CSS 중첩으로 생성 클래스명 반복을 줄여 해결했다. 예측5368B와 달리 실제 Next 산출물은5576B이며, 실제 값을 기준으로 통과를 판단한다. 한도는 변경하지 않았다. 바뀐 프레임·제목·삭제 확인과 실패한 관측만 선별 재확인했다.

최종 앱 타입, 변경 파일 lint, 운영용 빌드·성능·PWA·Hosting 산출물 검사가 통과했다. 빌드는 CSS 용량 초과를 해결하며2회 진행했다. history/viewer CSS는 raw5576B·gzip1721B, 공통 PanZoom은 CSS raw1118B·gzip534B와 JS gzip3411B로 기존 예산 안에 있다. 정적 파일145개·사전 캐시129개를 확인했다. 용량 검사이며 실행 속도 개선을 측정한 결과는 아니다.

## 증거와 확인 경계

상세 로그와 독립 설계·판정·검토, 체크리스트와 결정 기록은 ignored `output/delivery-photo-inspection-20261114/`에 남겼다. `repro-before.log`, `repro-mobile-before.log`, `long-title-before.log`는 실패 재현이다. `unit.log`, `browser-desktop.log`, `browser-mobile.log`, `browser-layout-final.log`, `browser-webkit-final.log`와 첫 WebKit의 변하지 않은 통과 사례가 최종 고유 검사 수의 근거다. `browser-label-final.log`는 최종 CSS에서 모바일 라벨 캡처를 갱신하는 집중 검사다. 빌드와 산출물 결과는 `build-final.log`, `performance-final.log`, `pwa-final.log`, `hosting-final.log`다.

실제 직원의 저장 사진이나 운영 데이터를 시험용으로 변경하지 않았다. 실물 휴대폰·설치 PWA·현장의 압축 사진 판독·인증된 운영 조작은 미검증이다. 이번 결과는 실제 컴포넌트와 합성 WebP를 사용한 로컬 UI 및 산출물 검증이다. 운영 Hosting은 이 작업으로 갱신하지 않았다.
