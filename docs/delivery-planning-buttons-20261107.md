# 납품사진 주요 버튼과 거래처 복귀

2026-11-07 로컬 구현. 운영 배포는 하지 않았다.

## 변경

- 사용자가 요청한 ‘대인’ 대화방의 납품사진 캡처를 확인했다. Kakao Bridge public preview로 상태·열린 창·화면을 확인하고, 첨부 다운로드 미지원으로 카카오톡의 사진 뷰어를 사용했다. 검색 입력을 변경하지 않았고 메시지·파일을 보내지 않았다.
- 명세서 등록은 겹친 문서 3장과 스캔하는 휴대폰, 경로 추천은 접힌 지도·경로·핀의 직접 제작 SVG를 사용한다. 외부 이미지·아이콘 라이브러리 추가 없음.
- 두 버튼은 차분한 블루/청록 표면과 두께가 있는 하단 그림자, 클릭 시 눌림 효과를 사용한다. 이전 `.workspace button`이 기본 배경·테두리를 덮던 문제는 전용 선택자 우선순위로 해결했다.
- 납품사진의 별도 복귀 버튼을 제거했다. 해당 화면에서 활성 ‘거래처’ 모드 클릭은 기존 `closeCustomerPage`로 연결하며, 다른 화면의 활성 모드 동작과 다른 모드 전환은 유지한다. 기존 기록 복원·브라우저 뒤로 가기·페이지 복원 시 홈 복귀 계약을 유지한다.
- 제목과 건수를 왼쪽에 묶고 순서 편집을 오른쪽으로 옮겼으며 검색창 주변 여백을 줄였다. 명세서/경로 추천 처리와 자동 적용 로직은 변경하지 않았다.
- SVG 두 개를 PWA precache에 추가했다. Hosting 검증은 정확한 파일 목록·해시·크기 및 원격 SVG MIME을 확인하도록 확장했다.

## 검증

- 실제 AppShell/납품사진/PlanningEntry 컴포넌트와 격리된 예시 데이터로 브라우저 36개 통과. 스타일 중복 정리 후 관련 4개 추가 통과. 320/390/430/1280px, 글자 200%, 강제 색상, 키보드 진입, 두 도구 열기, 홈 복귀, 뒤로 가기 및 복원된 페이지 복귀 확인.
- 관련 단위 14개·타입·lint 통과. 에뮬레이터 테스트의 기존 복귀 버튼 선택자 두 곳도 상단 모드 버튼으로 갱신했으나 이번 작업에서 해당 운영 쓰기 유사 시나리오의 에뮬레이터 실행은 하지 않았다.
- 첫 빌드의 테스트 튜플 타입 오류를 수정했다. 새 스타일이 기존 용량 한도를 넘은 것은 중복 선언 정리로 해결했고 성능 한도는 늘리지 않았다. 새 SVG의 precache 허용 목록도 명시적으로 보강했다. 최종 운영 build/PWA/Hosting/성능 gate 통과: 출고 129개·precache 116개, 초기 CSS gzip 6,504B, 납품사진 CSS 6,142B/1,885B gzip·JavaScript 10,471B gzip.
- 예시 거래처 미리보기: `output/delivery-planning-buttons/preview-390-mobile-chromium.png`. 실제 휴대폰·인증된 운영 저장 흐름은 별도 미검증.
- 서버·운영 데이터·인증 설정은 변경하지 않았다.
