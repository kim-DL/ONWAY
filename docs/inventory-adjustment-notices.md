# 직원 간 재고 변경 알림

운영 모드의 **직원 관리 → 직원 상세 → 재고 알림 수신 직원**에서 수신자를 지정한다. 지정된 직원은 **설정 → 재고 변경 알림**에서 모든 기기의 수신을 끄거나 다시 켤 수 있다. 최초 상태는 미지정이다.

## 변경을 한 번만 전달하는 경로

- 재고 상세의 **입고·출고·조정** 저장 시 알림을 전달한다. 입고·출고는 입력한 수량만큼 더하거나 빼고, **조정**은 유통기한별 묶음의 최종 수량을 저장한다. 서버는 실제로 바뀐 수량의 차이, 당시 상품명·단위, 보관 장소, 확정된 재고 버전을 알림에 기록한다. 카드와 알림함에 작업 종류를 표시하며, 종류 필드가 없는 기존 기록은 수량 조정으로 표시한다. 장소 이동·실사 확인과 차이가 0인 조정은 알림 대상에서 제외한다.
- 재고와 수신자 명단을 같은 Firestore 트랜잭션에서 읽는다. 본인을 제외한 수신자가 있으면 조정 요청 ID로 알림 한 건을 생성한다. 재고·이력·감사 로그·요청 영수증과 함께 커밋하므로 실패한 조정이나 이미 처리한 요청의 재시도에서 알림을 추가하지 않는다.
- 직원별 수신 설정은 기존 App Check·권한 검사를 사용하는 Callable로 저장한다. 직원은 자기 수신 여부를 바꿀 수 있고, 운영자는 지정 여부를 바꿀 수 있다. 요청 ID와 설정 버전을 검사하고 성공한 변경을 감사 로그에 남긴다.
- 수신자 명단은 서버 전용 문서다. 알림에는 해당 수신자들의 임의 식별자만 들어간다. 조회 규칙은 현재 직원·UID·역할·세션과 수신 설정을 대조하고, 해당 직원에게 전달된 알림만 허용한다. 개인 수신을 다시 켜면 앞서 받은 미확인 항목을 볼 수 있다. 지정 자체를 해제했다가 다시 지정하면 새 알림함으로 시작한다.

## 화면과 지난 기록

- PC에서는 우하단, 모바일에서는 하단 작업 버튼 위에 6초간 표시한다. 카드는 포커스와 터치를 가져가지 않는다. 연속된 변경은 최신 항목과 추가 건수로 묶는다.
- 열린 상품 상세의 수량이 알림보다 오래되면 변경 장소와 차이를 표시한다. **최신 수량 보기**를 누르면 상품과 묶음을 서버에서 다시 읽는다. 작성 중인 폼에는 변경량을 덧셈으로 적용하지 않는다.
- 온누리 로고의 점은 해당 직원의 미확인 알림을 나타낸다. 알림함을 열면 그 시점의 목록을 보여주고 마지막 알림의 시각과 ID를 서버에 저장한다. 열어 둔 동안에는 50건씩 이전 미확인 항목을 읽을 수 있다. 이후 도착한 건은 다음에 열 때 표시한다. 직원의 다른 기기도 같은 읽음 위치를 구독한다. 상품 이력은 해당 상품 상세에서 조회한다.
- 앱 시작·탭 복귀·재연결의 첫 응답은 조용히 목록만 갱신한다. 앱을 닫았을 때도 받으려면 각 기기의 **앱 설정 → 이 기기에서 알림 받기**를 켜고 운영체제 알림을 허용한다. 기기 알림에는 상품명과 해당 변경의 수량·장소·종류가 표시된다. 잠금 화면 미리보기는 기기 설정을 따른다.
- 서버는 알림 문서가 생성될 때 수신 지정·개인 설정·세션을 다시 확인하고 등록된 기기로 Web Push를 보낸다. 발송 키는 Secret Manager의 `INVENTORY_WEB_PUSH_VAPID`에서 관리한다. 앱을 여는 것만으로 브라우저 권한을 요청하지 않는다.

## 로컬 검증

재고 서비스 단위 테스트는 두 묶음 중 한 묶음만 조정했을 때의 차이, 충돌, 수량 일치, 동일 요청 재시도를 검증한다. Firestore 에뮬레이터 테스트는 수신 대상 쿼리, 타인 기록·직접 쓰기 차단, 수신 변경과 세션 해제를 다룬다. 브라우저 시나리오는 `tests/e2e-auth/inventory-flow.spec.ts`의 `inventory notices follow assignment`에 있다. 실행기는 격리된 `demo-inventory-e2e` 프로젝트를 사용한다.

2026년 11월 22일 로컬 검증에서 일반 테스트 2,162개가 통과했고 24개는 건너뛰었다. 격리된 Firebase 에뮬레이터 통합 테스트 14개와 직원 간 브라우저 시나리오도 통과했다. 브라우저에서는 PC와 모바일 터치 에뮬레이션으로 수량 조정, 수신 지정·해제, 개인 설정, 재연결, 과거 기록 조회를 확인했다. 정적 빌드는 기존 성능 예산과 PWA 검사를 통과했다.

운영 반영 대상은 Functions의 `recordInventoryMovement`, `assignInventoryNoticeRecipient`, `setInventoryNoticePreference`와 Firestore 규칙·인덱스, Hosting이다. 새 `inventoryNotices` 복합 인덱스가 준비되면 사용자 화면을 활성화할 수 있다.
