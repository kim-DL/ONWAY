# 재고 제품 상세 정보 가독성

사용자가 작업 버튼 개선을 확인하고 제품 상세에 표시되는 정보의 글자도 키우도록 요청했다. 앞선 [재고 작업 아이콘·문구 개편](inventory-action-icons-20261115.md)에 이어 같은 상세 화면을 다듬었다. 기준 main은 `025aa7a`, 브랜치는 `codex/inventory-detail-readability`다. 기존 유리·세라믹 표현, 중앙 정렬과 정보 순서를 유지했다.

## 점검과 변경

제조사·규격·원산지·기준 단위·박스 입수량 값과 유통기한 날짜가14px이었다. 보관 장소 선택은13px, 메모는13px, 실사 상태 배지는약10.24px로 읽기 어려웠다. 제품 상세 전용 CSS만 수정했다.

| 정보 | 변경 전 | 변경 후 |
| --- | --- | --- |
| 제품명 | 20px | 22px·700, 줄간격1.4 |
| 제조사·규격·원산지·기준 단위·박스 입수량 값 | 14px·500 | 18px·600 |
| 위 항목명 | 14px | 16px·줄간격1.4 |
| 유통기한 날짜·수량 영역 제목 | 14px / 16px | 18px |
| 유통기한별 수량 | 22px | 24px·숫자 간격 보정 제거 |
| 현재 재고 숫자 | 30–44px | 34–44px·숫자 간격 보정 제거 |
| 현재 재고 안내·단위·보관 장소 선택·제품 사진 안내 | 12–14px | 16px |
| 메모·추가 구분명·유통기한 경고·수정 버튼 | 13–14px | 16px |
| 실사/비활성 상태 배지 | 약10.24px | 14px·600 |

정보 셀의 세로 여백은8→12px, 본문 간격은9→12px로 조정했다. 긴 값은 기존 줄바꿈을 유지한다. 큰 수량·긴 단위·추가 구분명이 함께 있는320px 화면에서 날짜가 두 줄로 갈라지는 것을 관측했다. 날짜 영역은112px 이상 확보하고, 같은 행이 좁으면 수정 버튼이 다음 줄 오른쪽으로 이동하게 했다. 기본/긴 데이터의320·390·1280px에서 날짜가 한 줄로 표시되고 행 전체를 footer 위로 스크롤할 수 있다.

보관 장소 선택의 글자는16px 부모 폰트를 상속해 중복 선언을 남기지 않았다. 상세 제목과 상태 배지는 상세 본문에 한정한다. 공통 목록 옵션의 제목, 직전18px·700·색상 작업 버튼, 유통기한의 붉은 경고 의미는 유지했다. TSX·상태·권한·서버 호출·사진·저장/로그인 계약은 바꾸지 않았다.

## 확인

실제 `InventoryDetail`을 기존 로컬 합성 화면에 연결해 확인했다.320·390·1280px 각각 기본/긴 데이터6조건의 글자 크기와 줄간격, 본문 가로 넘침/잘림 없음, footer 작업 버튼의44px 이상 크기와 도달성, 제조사 등 긴 한글·공백 없는 영문·메모·999999 수량·긴 단위·복수 장소 선택·붉은 경고를 확인했다. 미등록3개 항목도 남고, Escape 닫기가 유지되며 JavaScript 오류는0이었다. 운영 데이터 읽기/쓰기는 없다.

첫 확인에서는 일반 제목 규칙이 뒤에 있어 상세의18px 제목을16px로 덮는 것을 발견했다. 상세 제목 범위를 명확히 해 해결했다. 이후 font/배치 확인은 통과했다. 긴 날짜의 분할은 후속 행 배치 보완으로 수정했고, 바뀐 행6조건만 재확인했다. 보관 장소의 중복 폰트 선언 제거 후 해당 선택16px만 별도로 확인했다. 실패/초기 관측을 최종 통과와 구분하며 이전 버튼·목록·서버 검사는 반복하지 않았다.

증거는 ignored `output/playwright/inventory-detail-readability-20261115/`의 합성 화면, `browser-check.log`(제목 실패), `browser-check-final.log`(폰트 확인), `rows-final.log`(행 배치), `select-final.log`(상속 확인), `final-390.png`, `final-320.png`, `stress-320.png`에 있다. 실물 휴대폰·설치 PWA·인증된 실제 재고 저장은 별도 검증하지 않았다.

## 운영 반영

앞선 재고 상세 개편의 배포 흐름으로 이어 진행한다. 최종 운영 빌드(타입 포함)와 성능·PWA·Hosting 산출물 확인이 첫 실행에 통과했다. 최초 JS gzip144050B, 재고 JS gzip25530B는 그대로다. 재고 CSS는raw31232B·gzip7007B이며 기존 raw 한도31232B에 도달했다. 예산을 높이지 않았다. 추후 재고 CSS 추가 시 기존 규칙 정리가 필요할 수 있다.

제품 CSS1개와 Hosting145개 파일의 해시를 고정했고 같은 산출물을 커밋·main 병합 후 Hosting `onnuriway`에만 배포한다. 이전 Hosting은 `4d17345b15479282`다. 전체 원격 CI·기존 버튼/목록/서버 검사는 반복하지 않는다. 빌드/산출물 로그와 고정 후보는 같은 증거 폴더의 `build.log`, `performance.log`, `pwa.log`, `hosting-build.log`, `release-candidate.json`이다. 최종 식별자와 배포/공개 확인은 완료 후 기록한다.
