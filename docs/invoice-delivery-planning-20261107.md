## 확정한 동작

- 납품사진 화면에 `명세서로 납품 준비`를 추가한다. 촬영 또는 갤러리에서 여러 장 선택 → 한 장씩 분석 → 확실히 일치한 거래처는 내 납품처/오늘 납품처에 자동 저장한다.
- 공급받는 자의 상호·주소만 매칭에 사용한다. 공급자와 품목 비고의 최종 수령처를 혼동하지 않는다. 괄호 지역명은 후보를 넓히는 보조 정보이며 지점 구분을 무조건 지우지 않는다.
- 이름과 주소가 모두 일치하고 후보가 하나일 때만 자동 저장한다. 날짜 불일치, 흐린 글자, 주소 불일치/미기재, 복수 후보는 직원이 기존 거래처를 선택해 확인한다. 전사 거래처 자동 생성은 하지 않는다.
- 직원별 내 납품처는 중복 없이 추가한다. 오늘 명시 목록이 있으면 합치고, 없으면 명세서 대상과 오늘 이미 촬영한 거래처로 시작한다. 이미 저장한 오늘 목록·완료 사진은 제거하지 않는다.
- 회사 출발 주소는 사용자 확인값 `대전 대덕구 우암동로17번길 10, 1층(비래동)`이다. 관리자 설정에서 지도 좌표를 선택·확인한다. 마지막 거래처 고정, 회사 복귀 없음. 추천 확인 후 오늘 순서만 적용한다.
- 차량은 봉고3 1톤 스탠다드 냉동탑차 기본값을 사용한다. 전체 높이 240cm, 폭 175cm, 길이 520cm, 적재량 1,000kg. 사용자 입력이나 제원 미설정에 따른 차단은 없다. 높이 제한 2.3m 이하 통과 불가 조건을 유지한다. TMAP 문서에 하상도로 일괄 제외 옵션은 확인되지 않아 제외 보장을 표시하지 않는다. 추천은 방문 순서 참고이며 하상도로·낮은 굴다리 통행 확인이 필요함을 화면에 표시한다.

## 기본 차량의 근거와 가정

- [기아 공식 봉고Ⅲ 냉동탑차 제원](https://www.kia.com/kr/vehicles/bongo3-frozen/specification/bongo3-frozen), 2026-11-07 조회: 1톤 베이스 **스탠다드** LPG 터보의 전체 높이 2,400mm, 전체 폭 1,750mm, 길이 킹캡 5,170mm/표준캡 5,200mm, 최대적재량 1,000kg. 내부 적재함 높이 1,450mm와 구분했다. 길이는 두 캡 중 긴 5,200mm를 채택했다.
- `DEFAULT_DELIVERY_VEHICLE` 한 곳에서 관리하고 UI와 서버가 공유한다. 차량 입력을 설정 저장 스키마에서 제거했다. 예전 설정의 차량 값이 없거나 다른 값이어도 서버는 고정 프로필을 사용하며 조회 과정에서 기존 문서를 덮어쓰지 않는다.
- 경로 API의 화물차 입력에는 적재량 외에 `truckTotalWeight`도 필요하다. 위 공식 제원에는 냉동탑차의 총중량이 없으므로 **4,000kg은 경로 계산용 보수 가정**으로 둔다. 제조사 공인 총중량·허용총중량·실제 적재 중량으로 주장하지 않는다. 실차 등록증이 확인되면 서버 상수만 수정 가능하며 사용자에게 제원을 입력시키는 UI는 없다.
- 기본값은 현재 공식 스탠다드 모델 기준이다. 사용 차량의 연식/개조/추가 장비를 실측한 결과가 아니며 모든 도로의 통행 안전을 보장하지 않는다. 하이(2,560mm), 로우(2,000mm), EV 스탠다드(2,410mm)와 혼용하지 않는다.

## 서버와 보존 계약

- 신규 Callable 전용 모듈. 기존 route/day/photo wire 계약은 변경하지 않는다. App Check·직원 세션/권한을 요청 시작과 최종 트랜잭션에서 확인한다.
- 명세서 이미지는 브라우저 메모리 → Callable 메모리 → OpenAI Responses의 base64 image 입력만 사용한다. Storage, Firestore, IndexedDB, 파일, 로그, 기존 납품사진 outbox에 저장하지 않는다. 이미지의 해시와 분석된 최소 텍스트/고객 ID만 재시도 영수증에 저장한다. `store:false`, Files/Background API 사용 없음. OpenAI 자체 데이터 보존 정책은 별개다.
- 서버에서 실제 이미지 형식·크기 확인 및 메모리 내 회전/축소. 구조화 출력 스키마로 인식 결과 검증. 모델의 문서 내 지시문은 데이터로만 취급한다.
- requestId+사용자+입력 fingerprint 영수증으로 재요청을 처리한다. 외부 API 호출 중 중복 호출/자동 재과금 금지. 불확실한 외부 실패는 같은 ID로 재호출하지 않고 명시적인 재시도만 새 요청으로 허용한다.
- 유료 호출은 직원별·회사 전체 일일 횟수 제한. TMAP은 회사 45회/일로 기본 제한(같은 키의 외부 사용은 집계 불가). OpenAI는 직원 60장/회사 250장/일. 응답 완료 뒤 권한 재검증. 비밀은 Secret Manager 서버 전용.
- 목록 추가는 트랜잭션으로 둘 다 성공/둘 다 실패. 현재 문서와 활성 거래처를 재검증하고 revision을 증가시킨다. 재고·입출고·사진 문서 자체는 수정하지 않는다. 감사 이력과 idempotency 영수증을 남긴다.
- 추천 요청은 현재 오늘 목록·거래처 좌표·설정 revision을 묶는다. 회사 출발에서 전체 방문 전 준비용으로만 제공한다. 납품사진이 이미 있으면 사무실 출발 경로를 재계산하지 않는다. 추천 적용 때도 날짜/목록/설정/거래처 revision을 확인한다. 새 사진·목록 변경 시 재확인 요구. 방문 누락·중복·종점 변경 응답을 거부한다.

## 변경 단위

1. 공유 순수 스키마, 상호/주소 매칭, 이미지 처리 및 OpenAI/TMAP adapter.
2. 설정 조회/관리자 저장, 분석/확인 등록, 추천/순서 적용 서비스와 Callable. 기존 컬렉션에 추가만 하고 별도 설정/영수증 컬렉션은 클라이언트 접근 금지 규칙을 유지한다.
3. 지연 로드되는 납품 준비 BottomSheet. 진행률·확인 필요·저장 완료를 구분하고 파일별 실패/재시도 제공. 확정 후 이미지 참조 해제. 설정 화면은 관리자만 변경.
4. 실제 컴포넌트로 격리된 로컬 미리보기와 모바일 캡처. 예시 데이터/모의 API임을 명확히 표시한다.

- 새 UI의 별도 지연 로드 한도: JS 8KiB gzip / CSS 9KiB raw·2.5KiB gzip. 진입부는 JS/CSS 1.5KiB. 초기 JS/CSS와 기존 CSS 한도 유지. 공유 거래처 chunk 측정 36,939B에 맞춰 128B, 납품사진의 진입 경계 측정 10,450B에 맞춰 256B만 관련 한도 추가.
- 중간 발견/수정: 축약 도시명 주소 충돌 보완, 신규 서버 수에 맞춘 identity 검사, esbuild 정규식·보안 문맥 fixture·select 접근성 선택자 수정. 새 CSS가 legacy로 계측되던 부분은 독립 경계/예산으로 분리했다. 실패 결과를 통과로 합산하지 않았다.
- 차량 기본값 후속 수정 검증: 관련 단위 **27개**, Firestore 에뮬레이터 **16개**, 모바일/PC 브라우저 **6개**, 앱/Functions 타입 및 관련 lint 통과. 출발 좌표만 설정하면 추천이 가능하고 차량 재입력이 필요 없음을 확인했다. 새 설치/예전 null·사용자 제원에도 동일 기본값 적용, 클라이언트 차량 변경 거부, 기존 문서 조회 무변경, 총중량과 cm/kg 변환을 확인했다. 외부 API는 모의 호출이며 위 전체 회귀/Hosting 빌드는 후속 수정 전 결과다. 배포 시 최종 소스를 다시 빌드해야 한다.
- 후속 화면 캡처: `output/playwright/delivery-planning-bongo-default.png`, `delivery-planning-origin-only.png`. 미리보기 서버를 최종 소스로 재시작했다.

## 운영 연결 전 남은 조건

1. `OPENAI_API_KEY` 등록·전용 계정 접근 연결 완료. `TMAP_APP_KEY` 발급·연결은 로그인 완료 후 진행. `INVOICE_OPENAI_MODEL` 기본값은 `gpt-6-luna`.
2. 승인된 회사 주소의 정확한 지도 좌표를 확인해 기본값 반영 완료. 차량 제원 입력은 폐지했으며 위 공식 치수와 별도 표기한 총중량 가정을 서버 기본 프로필로 사용한다.
3. 새 전용 키로 실제 명세서 인식과 운영 거래처 읽기 대조 완료. 실제 경로 API 및 무료 상품 접근 검증은 남아 있다.
4. 문서의 화물차 치수 조건을 사용하지만 하상도로 일괄 제외 옵션은 확인되지 않았다. 모든 제한 구간의 배제를 보장하지 않는다. 실제 차량 경로·폰 카메라·PWA·현장망 인수 필요.
5. 사용자 화면 승인 후 신규 Functions 6개를 먼저 배포하고 Hosting은 `--project onnuriway --only hosting:onnuriway`로 별도 진행한다. 기존 재고/사진 서버를 이 기능 때문에 재배포할 필요는 없다.
