# 모바일 중심 로딩·브랜드 개선

기준일: 2026-10-30. 사용자가 기존의 단순한 선형 모션을 유지하면서 시작 로딩을 모바일 중앙으로 옮기고, 온누리 로고를 확대해 배경판 없는 입체감으로 표현하도록 요청했다. 필요한 업무 로딩 확장과 최종 main 병합·Hosting 배포도 승인했다.

## 적용

- 코드 준비·세션 확인·업무 화면 준비의 브랜드와 안내를 하나의 중앙 그룹으로 배치했다. 모바일 기준 로고 폭 144px, 안내 17px, 선 길이 160px이며 기존 2px 두께와 모션을 유지한다. PIN 헤더는 투명 로고를 72px 폭으로 사용하고 입력·버튼·관리자 로그인·도움말의 배치와 기능을 유지한다.
- 원본 온누리 물결의 색·형태·명암을 유지하고 투명 윤곽에 은은한 고정 그림자만 더했다. 배경판·광택 반복·새 등장 모션은 없다. 고대비에서는 그림자를 제거한다.
- 원본 1200×446 PNG 278,308B를 인증 화면에서 직접 내려받지 않도록 기존 자산 생성기에 576×214 WebP 파생 파일을 추가했다. 28,962B이며 같은 크기로 축소한 원본과 alpha 채널이 동일하다. 별도 아트 생성이나 새 라이브러리·폰트는 없다. 정확한 공개 파일 한 개만 PWA allowlist와 precache에 추가했다.
- 시작 화면은 safe-area와 짧은 가로 화면을 고려해 내용이 커지면 스크롤할 수 있다. 3초 뒤 보조 문구가 생겨도 로고·안내·진행선이 이동하지 않도록 공간을 예약했다. 200% 글자 확대에서도 선과 중앙 그룹이 화면 너비를 넘지 않는다.
- 납품사진의 오늘 목록·목록 갱신·최근 이력·원본 조회·확대 기능 준비에 같은 `LoadingStatus`를 적용했다. 원본 사진 로딩은 사진 영역 중앙에 배치하고 어두운 배경에서 선과 글자가 읽히도록 색을 조정했다. 갱신 중 기존 목록·입력·준비된 사진을 유지한다.

## 보존 계약

1초/3초 기준, 단계 간 공유 시계, 완료 즉시 전환, 단일 상태 낭독, 동작 줄이기·사용자 모션 정지·백그라운드 정지를 유지한다. 오프라인 복구는 기존 정적 안내를 사용한다. PIN 잠금·실패 후 포커스, 인증·세션 정책, Callable·App Check·권한·revision·request ID·감사·사진 보관·서버 확인 후 완료 로직은 변경하지 않는다. 업무 헤더와 인사 모션, 설치 아이콘은 변경하지 않는다.

## 로컬 검증

- 인증·로딩·브랜드 관련 unit 71 PASS, 사진 관련 unit 38 PASS. 최종 경량 자산·PWA·공통 로딩 관련 30 PASS와 auth/브랜드/스켈레톤 관련 15 PASS를 별도로 실행했다. 묶음 간 중복이 있으므로 합산하지 않는다.
- 사진 브라우저 12 PASS / 기존 기기별 2 SKIP, 최종 대비 확인 2 PASS. 지연 응답에서 1초 표시·3초 설명·단일 상태·중앙 정렬·접근성·응답 후 즉시 전환을 확인했다.
- 로딩 전체 검사 27 PASS / 1 FAIL 뒤 320px·글자 200% 넘침을 수정했다. 최종 해당 검사 1 PASS, 반응형·새 배치 검사 10 PASS다. 나머지 시간·PIN·실패·연결 복구 검사는 변경 후 기존 조건 그대로 통과했다.
- 320·390·768·840·1280px, 844×390 가로 화면, 글자 200%, 동작 줄이기·고대비·axe와 요소 경계 확인을 포함한다. 화면 중앙, 1초/3초 전환 시 위치 유지, PIN/관리자 버튼 접근을 확인했다.
- 앱·Functions typecheck, 전체 lint PASS. 운영 형식 정적 결과의 390/1280px에서도 중앙 그룹의 x/y 중심 오차 1px 미만, 가로 넘침 0, PIN 입력 가능, pageerror 0, 로고 HTTP 응답과 파일 내용 일치를 확인했다.
- 최종 build·PWA·성능·Hosting gate PASS, 로컬 정적 HTTP 26개 검사 PASS다. initial JS gzip 143,643B, 학교/공통 CSS gzip 47,194B, 납품사진 JS gzip 10,223B, 사진 이력 CSS raw 5,620B로 기존 모든 한도를 유지했다. 최종 사진 CSS 정리 후 사진 브라우저 12 PASS/기존 2 SKIP, 이력 unit 6 PASS다.

후속 예산 검사에서 사진 이력 CSS raw 6,019B가 5,632B를 초과한 것은 중복 focus/media/선택자를 합쳐 5,620B로 줄였다. 새 공개 로고가 Hosting 검증기의 별도 allowlist에도 필요해 정확한 파일만 추가하고, 경량 WebP 형식·검토 자산과의 일치·원격 MIME/해시 검사를 보강했다. 기존 공개 HTTP 25개 조건에 로고 GET 검사를 더해 26개가 됐다.

초기 실패와 조치: 테스트 fixture의 Window 형식 선언을 보완했다. 확대 시 진행선의 intrinsic minimum이 부모 grid를 넓히던 문제는 `min-width: 0`과 `minmax(0, 1fr)`로 수정했다. 초기 자산 테스트의 완전 불투명 픽셀 수 가정은 원본부터 맞지 않아 원본과 alpha 채널을 비교하도록 바로잡았다. 첫 빌드의 학교/공통 CSS 한도 52B 초과는 중복 인증 스타일 정리로 해결했고, 다음 빌드의 납품사진 JS 한도 10B 초과는 중복 보조 문구를 간결하게 통일했다. 검사 한도·assertion·timeout·skip·재시도 정책은 완화하지 않았다.

최종 운영 빌드·전체 CI·main·Hosting 결과는 후속 [릴리스 기록](releases/2026-10-30-mobile-loading.md)에 기록한다. 브라우저 증거는 합성 컴포넌트와 익명 정적 페이지 기준이며 실제 직원 기기·설치 PWA의 OS 시작 화면·장시간 세션 인수와 구분한다. 속도 개선 수치를 새로 주장하지 않으며 인위적인 작업 지연을 추가하지 않았다.
