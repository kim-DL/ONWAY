# 동선 선택·대규모 경로·헤더 정리 — 2026-09-05

## 범위와 보존 사항

- 기존 흰색/중립 배경과 파란색 주요 동작 테마를 유지한다.
- 설치용 PWA 아이콘, 원본 로고 파일, 직원/학교/방문 기록은 변경하지 않는다.
- 학교 배정 권한, 현재 운영 월 검증, App Check를 유지한다.
- 운영 앱에 직접 반영한다. 새 미리보기 배포를 만들지 않는다.

## 40곳 이상의 담당 학교

앱 동선 상한을 20곳에서 50곳으로 확장한다. 카카오의 **요청당 목적지 30개**
한도와 앱의 전체 학교 수는 별개다. 각 출발지에 대해 목적지를 30개 이하로
나누어 호출하며, 가까운 구간을 우선 배치한다. 최대 동시 요청은 4개,
도로 조회의 새 요청 예약은 18초, 개별 HTTP 요청은 6초로 제한한다.
시간 또는 공급자 오류 때문에 조회하지 못한 구간은 전체 방향별 거리 추정
행렬에 남긴다. 요청한 학교를 조용히 제외하거나 첫 20곳만 결과로 내보내지 않는다.

결과·브라우저 저장 계약 모두 최대 50곳/2,450개 방향별 구간을 수용한다.
최적화는 첫 학교를 고정한 최근접 탐색과 최대 20회의 2-opt 개선이다.
수학적 최적해나 미래 교통 상황, 방문·주차 시간을 보장하지 않는다.
카카오 반경 제한(10km) 등으로 도로 구간을 확인하지 못하면 추정 표시를 유지한다.

위치 확인 성공은 기존 매칭 서비스가 저장한다. 새 학교의 확인이 시간 예산을
넘기면 선택을 유지하고 다음 시도에서 미완료 위치를 이어서 확인한다.
미확정 학교 ID 복구 목록도 20개로 잘리지 않도록 함께 확장했다.

참고: [카카오 다중 목적지 길찾기 공식 문서](https://developers.kakaomobility.com/guide/navi-api/destinations.html).

## 별도 결과 거부 오류

조회된 도로 구간이 일부 있어도 실제 추천 순서에는 추정 구간만 쓰이는 경우가
있다. 서버는 예전에 전체 행렬의 도로 구간 개수로 `hybrid`를 지정했고,
클라이언트는 실제 추천 순서 기준으로 검증하여 유효한 결과를 거부할 수 있었다.
서버도 실제 추천 순서의 구간을 기준으로 모드를 결정하도록 맞췄다.
이 오류는 계산 응답 이후 문제이며, 첫 학교 선택 직후의 화면 문제와 구분한다.

## 흰 화면의 재현과 수정

실제 BottomSheet와 40개 학교 fixture에서 대전선화초등학교를 첫 학교로
선택한 뒤 대전외국어고등학교를 선택하면 흰 화면이 재현됐다. JS 예외는 없었고,
외곽 dialog 스크롤도 0이었지만 내부 `.bottom-sheet`의 스크롤이 509px에서
1,049px로 변했다. 고정 footer의 화면상 top은 -305px까지 올라갔다.
위치가 지정되지 않은 absolute 라디오 입력에 포커스가 가면서
`overflow:hidden` 부모까지 스크롤되는 것이 원인이었다.

첫 학교 선택을 `aria-pressed`가 있는 실제 버튼으로 교체하고, 학교 체크박스는
relative 레이블 안에 위치를 고정했다. 수정 후 부모 스크롤 0/footer top 744px
(390×844 화면)을 유지한다. 공통 BottomSheet와 globals.css는 변경하지 않았다.
첫 학교·선택 개수 요약, 미완료/전체 일괄 선택의 상태와 개수를 추가했다.
미완료 선택은 방문 완료를 제외한 학교를 선택하며 다른 학교를 목록에서 숨기는
필터가 아니다. 선택 범위 변경 후에도 기존 첫 학교가 범위 안에 있으면 보존한다.

## 카드와 헤더

- `before`이면서 방문 ID·날짜가 없는 학교에서만 unknown 전달 칩을 숨긴다.
  저장된 전달/미전달은 항상 보이고, 기록이 있는 학교의 unknown도 숨기지 않는다.
  화면과 접근성 이름에 같은 조건을 사용한다.
- 담당 제외가 잠긴 이유를 공동 담당/업무 기록/기타로 구분한다.
- 헤더의 이름 아바타를 제거하고 모드 선택 영역을 확장한다. 계정 정보는 설정에 남는다.
- 회사명 서체·크기는 보존하고 헤더 로고 그림만 85%로 축소한다.
- 납품 선택선은 파란색, 영업 선택선은 브랜드 녹색이다. 18초 회전 테두리는
  CSS로만 구현하며 저장되는 정지 설정, OS reduced-motion, forced-colors를 따른다.
- PWA 캐시를 phase24로 갱신한다. 설치 아이콘 파일은 수정하지 않는다.

## 검증 기록

- 서비스 단위 검사: 31/40/50곳, 학교 누락/중복 없음, 요청당 목적지 30개 이하.
- 40곳 각각을 첫 학교로 삼은 전체 서비스 응답이 클라이언트 무결성 검증 통과.

- 타 직원 담당/종료 월 거부, 잘못된 결과·중복·누락 구간 거부 유지.
- 단위 검사 353개 통과, 기존 NEIS 에뮬레이터 전용 3개 조건부 제외.
- 독립 실제 컴포넌트 브라우저 검사: 동선 10개, 카드 16개, 헤더 14개 통과.

  실제 PIN 로그인, 선화초/외국어고 시작 40곳 callable 계산, 전체 구간 무결성,

  forced-colors 및 axe 검사 통과. 시트 부모 스크롤이 0인지 확인한다.
- ESLint, Next 빌드, 최종 TypeScript 및 PWA 빌드 검사 통과.
