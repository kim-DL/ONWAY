# Phase 32 — 거래처 모드

## 1. 기능과 범위

- 기존 마지막 모드 기억과 역할별 접근을 유지하고, 허용 모드 앞에 `거래처`를 추가했다. 내부 `delivery` 값은 유지하며 화면 명칭은 `학교납품`으로 변경했다.
- 거래처명 완전·앞부분·부분·초성 검색, 공백·일반 특수문자 정규화. 주소·행정동·연락처·출입비밀번호·메모는 검색 대상이 아니다.
- 검색 카드에서 자치구·행정동, 출입비번, 실제 납품 위치 설명, 대표 연락처와 상태 배지를 바로 제공한다.
- 거래처 선택 시 앱 내부 지도, 실제 납품지점 단일 핀, 지도 조작·확대·축소·재중심·핀 정보 및 상세 연락처를 제공한다. 좌표가 없으면 임의 위치를 표시하지 않는다.
- 전화와 카드 선택은 별도 동작이며, 폐업 거래처의 전화·길찾기는 확인 후 실행한다. 길찾기는 기존 카카오 좌표 링크를 재사용한다.
- 관리자 화면에서 등록·수정·폐업 처리, 주소/장소 검색, 실제 핀 위치 조정, 좌표 직접 입력, 행정동 자동 확인·수정, 복수 연락처·대표 연락처를 관리한다.
- 핵심 정보 변경 시 `정보변경`, 신규 등록 시 `신규` 배지를 자동 지정한다. 관리자가 배지를 해제할 수 있다.
- 저장 버전 충돌과 중복 요청을 차단한다. 저장 응답이 불명확하면 동일 내용·동일 요청으로 확인하며, 늦게 도착한 위치 검색 응답이 저장 내용을 바꾸지 않는다.
- 일정·동선·즐겨찾기·납품 완료·OCR·외부 공유·ERP·운영 샘플 데이터는 추가하지 않았다.

## 3. Firestore 컬렉션 및 필드

기존 운영 프로젝트는 단일 회사 프로젝트이며 별도 회사 클레임이 없다. 기존 로그인 구조를 바꾸지 않고 고정 경로 `companies/onnuri/customers/{customerId}`를 사용한다. 회사 식별자는 클라이언트 입력으로 받지 않는다.

| 분야 | 필드 |
|---|---|
| 식별·검색 | customerId, companyId, name, normalizedName, choseongName |
| 위치 | district, administrativeDong, officialAddress, deliveryAddress, deliveryLocationDescription, deliveryPoint `{latitude, longitude}` 또는 null |
| 출입 | accessPassword 문자열, accessPasswordState `registered/none/unknown` |
| 연락처 | contacts 배열: id, name, role, phoneNumber 문자열, isPrimary |
| 상태 | status `active/closed`, noticeType `none/new/changed`, changeNote |
| 수정 관리 | revision, createdAt/updatedAt Timestamp, createdBy/updatedBy 직원 ID |

위도·경도는 숫자, 전화번호·비밀번호는 문자열이다. 연락처가 있으면 대표 연락처는 정확히 하나이다. API 응답에서만 Timestamp를 ISO 문자열로 변환한다.

`requestLocks/customer-{requestId}`에는 요청 해시·직원 식별자·거래처 ID·버전만 저장한다. 감사 로그에는 생성/수정 종류와 버전·상태 등 메타데이터만 저장하며 전화번호·비밀번호·주소·좌표·메모의 사본은 남기지 않는다.

## 4. Security Rules와 서버 권한

- 고정 회사 경로에서 현재 유효한 세션과 활성 직원 문서·Firebase UID가 일치해야 조회 가능하다.
- 직원의 직접 생성·수정·삭제는 관리자라도 차단하고, 서버 검증을 통과한 관리자 callable만 저장한다.
- 관리자 쓰기는 Google 인증·관리자 승인·실제 역할·현재 세션/권한 버전을 확인하고 트랜잭션 안에서 다시 검증한다.
- 다른 회사 경로, 미인증, 비활성, 만료된 버전, 회사 직원 문서가 없는 계정은 차단한다.
- 운영 callable에는 App Check를 적용하고 응답은 `private, no-store`이다.
- 거래처 응답은 localStorage·sessionStorage·IndexedDB·서비스 워커에 저장하지 않는다. 로그아웃·권한 상실·오프라인 시 민감 화면을 비운다.
- 권한 상실 시 기기 저장소 정리를 기다리지 않고 먼저 인증 화면을 전환한다. 정리 중 들어오는 과거 인증 응답은 폐기하며, 새 로그인은 이전 종료 처리가 끝난 뒤 허용한다.
- 공개 지도 SDK에는 지도에 필요한 좌표와 거래처 이름만 전달한다. 출입비번·전화번호는 마커 제목·URL·분석/오류 로그에 전달하지 않는다.

보안 검증은 아래 테스트와 코드 리뷰 범위에 대한 결과이며, 무결점 보안 보증을 의미하지 않는다. 회사 분리 정책이 바뀌면 고정 회사 경로와 직원 소속 판정을 함께 재설계해야 한다.

## 5. 인덱스

추가 복합 인덱스는 없다. 목록은 문서 ID 커서로 250개씩 읽고, 이름 검색은 클라이언트 메모리에서 수행한다. `customers`의 불필요한 자동 단일 필드 인덱스를 비활성화해 민감 문자열·배열의 인덱스 저장을 줄였다. 문서 ID 페이지 구분은 유지한다.

## 6. 환경변수와 카카오 설정

- `NEXT_PUBLIC_KAKAO_MAP_JAVASCRIPT_KEY`: 지도 JavaScript SDK용 공개·도메인 제한 키. REST/Admin 키를 넣으면 안 된다. 소스에 하드코딩하지 않는다.
- `KAKAO_REST_API_KEY`: 기존 Functions 비밀키 재사용. 주소/장소 검색 및 행정동 역조회에만 서버에서 사용한다.
- 카카오 앱 `1555434`의 카카오맵 사용은 이미 켜져 있음을 확인했다.
- 기존 JavaScript 키를 Vercel 운영 환경변수에 등록했다. REST/Admin 키와 별개인 공개 지도 키이며 소스·보고서에 값은 기록하지 않는다.
- 사용자 확인 후 카카오 콘솔을 다시 읽어 해당 JavaScript 키의 SDK 허용 도메인에 `https://onnuriway.vercel.app`이 정상 저장된 것을 확인했다. 초기 로딩 중 빈 상태와 구분해 재확인했으며, 중복 등록·키 재발급·다른 도메인 변경은 하지 않았다.
- 운영 도메인의 독립 브라우저 세션에서 실제 SDK와 지도 타일 로딩을 확인했다. 운영 거래처 데이터가 아니라 공개 장소(대전광역시청)를 브라우저 메모리에만 표시해 키·도메인 연결을 검증했다.

행정동 자동 입력은 카카오 역조회 결과 중 `region_type = H`만 사용한다. 법정동으로 임의 대체하지 않는다. 서비스 오류나 결과가 없으면 관리자가 직접 확인·입력한다.

## 7. 데이터 마이그레이션

기존 학교·영업·직원 데이터 마이그레이션은 없다. 거래처는 관리자 화면에서 신규 등록하며 검색용 필드와 수정 메타데이터는 서버에서 생성한다. 기존 카카오 즐겨찾기나 외부 명세서를 자동 가져오지 않는다. 운영 DB에 테스트 거래처를 넣지 않는다.

관리자 통합 검증은 실제 Firebase 에뮬레이터 인증·권한·저장 함수를 이용한다. 생성→재조회→수정→폐업→배지 해제, 저장 응답 유실→동일 요청 재확인→중복 없음, 긴 폼의 고정 저장 버튼, 닫기/브라우저 Back 거절·승인을 확인했다. 직원 검증은 이름만 검색되는지, 전화와 카드 클릭 분리, 비밀번호 선행 0 보존, 기기 저장소/URL 비노출, 오프라인/로그아웃/권한 상실 시 제거를 포함한다.

자동 지도 컴포넌트 검증에는 계약에 맞춘 모의 SDK를 사용했다. 별도로 운영 도메인에서 **실제 카카오 SDK·지도 타일·핀 로딩을 확인했다.** 공개 장소 조회, 타일 9개 로드, `tilesloaded` 3회, 실제 마커 클릭, 확대 level 3→2·축소 2→3, 드래그 후 핀 유지와 재중심을 확인했다. 캡처는 `output/phase32-kakao-sdk-mobile.png`에 남겼다. 이 외부 연결 검증은 공개 장소를 임시 DOM에 표시한 것이며, 운영 거래처 등록·저장 통합 테스트와는 구분한다(고객 API 호출 0회). 검증용 독립 세션을 닫고 임시 환경변수 파일도 제거했으며 기존 로컬 설정은 보존했다. 실제 통화와 물리 기기 터치는 아래 수동 검증 항목이다.

첫 통합 실행에서는 여러 시나리오의 로그인 누적으로 기존 10분 30회 보안 제한에 도달했다. 로컬 fixture를 격리·초기화한 최종 39개 실행은 전부 통과했으며 운영 제한은 변경하지 않았다. 병렬 CPU 부하가 큰 단위 실행에서 기존 검색 50ms 시간 기준을 한 차례 초과했으나, 동시 실행을 제한한 최종 전체 실행은 기준 변경 없이 통과했다.

- Android/iPhone PWA에서 전화 버튼이 기본 전화 화면을 여는지(실제 통화는 자동 실행하지 않음).
- 실제 현장 네트워크에서 지도 타일·핀치·지도 조작과 페이지 스크롤 전환.
- 가상 키보드가 열린 관리자 폼에서 하단 저장 버튼, 운영체제 뒤로가기·닫기 취소.
- 실제 납품지점 좌표·행정동·대표 연락처의 업무 담당자 검수.
- 운영 Google 관리자 팝업 로그인. 로컬 관리자 UI 검증은 에뮬레이터 Google credential과 실제 관리자 활성화/권한 검증을 사용했고, 팝업 전달 과정 자체와 구분한다.

## 11. 제한사항

- 지도 서비스는 네트워크·카카오 키/도메인/쿼터에 의존한다. 오류 시 주소·납품 안내·전화는 유지한다.
- 거래처 민감정보는 오프라인에서 제공하지 않는다.
- 현재 제품에는 별도 다크 모드가 없어 기존 밝은 테마와 토큰을 유지했다. 강제 색상/동작 줄이기 및 접근성 점검을 별도로 수행한다.
- 수십~수백 거래처 규모를 대상으로 전체 목록을 페이지 단위 조회한다. 5,000건을 넘어서는 비정상 범위는 조용히 잘라 표시하지 않고 오류로 처리한다.
