# Phase 33 — 거래처 홈·등록·관리자 내비게이션

## 변경 범위

2026-09-06 사용자의 후속 요청을 기준으로 Phase 32 기능을 다듬었다. 기존 파랑·중립색, 오로라 배경, 회사 로고, 웰컴 타이핑·마스코트를 유지한다. 이번 작업에서 서버 계약, 권한, 운영 거래처 데이터는 변경하지 않는다.

- 등록 폼에서 자치구·행정동 입력과 자동 역조회를 제거했다. 거래처명 → 공식 주소 → 실제 납품 주소 순서로 입력하며 주소 검색, 실제 납품 지점 핀, 연락처·출입 정보와 고정 저장 버튼은 유지한다.
- 새 거래처는 지역 필드가 빈 값이어도 기존 서버 계약으로 저장된다. 기존 거래처를 편집하면 과거 지역 메타데이터는 보존한다. DB 마이그레이션이나 데이터 삭제가 필요하지 않다.
- 검색 카드·최근 목록·관리자 목록의 기본 위치 정보는 실제 납품 주소를 우선하고, 없으면 공식 주소, 둘 다 없으면 ‘주소 미등록’이다. 임의 지역 추정이나 좌표 생성은 하지 않는다.
- 거래처 홈은 시간대별 인사, 짧은 제목, 검색, 최근 검색 거래처 순서로 구성했다. 큰 빈 안내 화면을 클릭 가능한 간결한 빈 상태로 교체했다. 최초 화면에 임의 거래처를 채우지 않는다.
- 관리자 모바일 하단 메뉴는 운영·거래처·학교·직원·더보기의 한 줄이다. 학교 배정·데이터 동기화·CSV·감사 기록·설정은 더보기 시트로 이동했다. 데스크톱에는 모든 9개 메뉴가 그대로 있다.

## 최근 검색 거래처의 기준과 개인정보

검색 결과에서 실제로 선택한 거래처만 최신순으로 최대 5곳을 기록한다. 재선택하면 맨 위로 이동하며 중복되지 않는다. 검색어 입력이나 목록 조회만으로 기록을 만들지 않는다. 최근 행을 다시 열어도 최신 순서로 갱신한다.

기기에는 `onnuriway:private:recent-customers:v1:{uid}:{sessionVersion}:{permissionsVersion}` 키에 거래처 식별자 배열만 저장한다. 이름·주소·좌표·전화·출입 비밀번호·검색어는 저장하지 않는다. 화면에 필요한 정보는 항상 현재 직원 권한으로 받은 최신 거래처 목록에서 해결한다. 삭제되거나 조회 권한이 없는 식별자는 표시하지 않는다.

- 페이지/모드 복귀·새로고침 후 유지된다. 로그아웃과 기존 private 상태 정리 시 삭제된다.
- 계정·세션·권한 버전이 바뀌면 다른 기록을 사용한다. 초기 빈 카탈로그가 저장된 ID를 지우지 않는다.
- 오프라인·권한 오류에서는 기존 민감 화면 제거 정책을 유지한다.
- 기기 저장소 차단/손상은 앱 오류로 전파하지 않는다. 저장이 차단되면 현재 화면 수명 동안만 최근 선택이 작동한다.
- ‘기록 지우기’는 확인 후 검색 기록만 지우며 실제 거래처 데이터는 삭제하지 않는다.

## 접근성과 성능

최근 행 전체를 터치할 수 있고, 주소는 줄바꿈을 허용한다. 초점 표시, 작은 화면, 글자 확대, 강제 색상, 동작 줄이기 및 브라우저 Back을 확인한다. 관리자 메뉴는 최소 44px 터치 영역과 safe-area 하단 여백을 확보한다. 더보기는 기존 BottomSheet를 사용해 키보드 초점을 가두고 닫은 뒤 초점을 복원한다.

별도 UI/애니메이션 라이브러리를 추가하지 않았다. React 스킬의 저장소 최소화·지연 로딩 원칙에 맞춰 거래처/편집기/지도 코드 분리를 유지했다. 프런트엔드 디자인 스킬은 기존 프로덕션의 색상과 밀도를 우선하는 데 적용했다.

새 관리자가 대체한 미사용 전역 CSS 원본 4,501 bytes를 제거했다. 공용 아바타·로그인·브랜드 규칙은 보존했다. 거래처 홈과 최근 ID 저장 기능에 한해 지연 로딩 예산을 CSS 원본 21KiB/gzip 5KiB, JS gzip 19KiB로 명시했다. 새 관리자 내비게이션 CSS도 관리자 전용 지연 로딩 파일로 분리되어 원본 7KiB/gzip 1.75KiB 상한을 따로 둔다. 빌드 검사는 이 CSS가 로그인 및 직원 업무 진입점에 섞이지 않는지도 검증한다. 기존 최초 로딩·영업·공용 CSS 제한은 완화하지 않는다. PWA 캐시 버전은 `phase33`이다.

## 검증 및 배포 기록

모든 쓰기 검증은 `demo-onnuriway` 로컬 에뮬레이터에서 수행하며 운영 거래처를 추가·수정하지 않는다. 실제 휴대폰 키보드·통화 실행 및 물리 기기 조작은 자동 브라우저 검증과 구분한다.

| 항목 | 최종 결과 |
|---|---|
| 전체 단위 테스트 | 667 통과, 기존 3개 건너뜀 |
| 거래처 API·직원·관리자 통합 | 10 통과, 최적화 빌드 + 실제 Firebase 에뮬레이터 사용 |
| 관리자 메뉴·기존 업무 모드 헤더 | 실제 React 브라우저 40 통과(모바일/데스크톱) |
| 접근성 | 최근 5곳 320/390/768px, 카드·상세·등록 폼·내비게이션 자동 위반 0 |
| 코드 품질 | ESLint, 앱·Functions TypeScript, diff 검사 통과 |

통합 시나리오는 주소 우선순위·초성 검색·전화/카드 충돌 없음·지도 오류 대응·최근 5개 제한/중복/재정렬·화면 복귀/새로고침·검색 기록 삭제 취소/승인·로그아웃/권한 상실/오프라인 제거·기기 저장소 민감정보 비노출을 포함한다. 관리자 검증은 지역 입력 없이 등록·수정·폐업·배지 해제, 지도 핀, 고정 저장 버튼, 닫기·Back 보호, 응답 유실 후 동일 요청 재시도와 중복 없음까지 확인했다.

첫 관리자 실행은 로컬 초기 목록 응답이 5.846초 걸려 기존 5초 UI assertion 제한을 초과했다. 응답 후 ready 전환은 31ms였다. 고정 sleep이나 제품 보호 로직 완화 없이 HTTP 응답(최대 15초)·응답 스키마·UI 활성화를 각각 확인하도록 테스트를 수정했다. 단독 재검증 및 최종 전체 10개 통합 검증이 통과했다.

일반 운영 설정의 `npm run build`, PWA 캐시/에셋 검사와 성능 기준 검사를 모두 통과했다. 최초 JS gzip 139,361 bytes, 기존 공용 CSS gzip 51,970 bytes, 관리자 전용 CSS gzip 1,549 bytes, 거래처 전용 CSS gzip 4,652 bytes 및 JS gzip 19,161 bytes였다. 영업 workspace JS gzip 12,970 bytes는 유지된다. 최종 390px 캡처에서는 최근 5개 행 모두 하단 바 위에 들어오며, 더 좁거나 글자가 커진 화면에서는 정상 스크롤로 접근할 수 있다.
