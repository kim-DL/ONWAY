# Phase 34 — 거래처 입력 간소화·직원 편집·상세 경험

## 요청 반영

2026-09-06. 기존 학교 납품 홈의 글꼴·타이핑 인사·검색 진입점·오로라 배경을 공유한다. 거래처 전용 큰 흰색 히어로 카드를 없애고 제목을 **거래처 정보를 한눈에.**로 변경했다. 최근 검색 거래처는 실제 선택한 최신 5곳만 표시한다. 거래처 모드의 선택 강조선은 민트 `#16a08f`, 선택 글자는 짙은 민트 `#087f75`이며 학교 납품·영업의 기존 색상은 유지한다.

모든 활성 직원에게 홈의 거래처 등록과 상세 하단의 정보 수정 기능을 제공한다. 관리자 전용 학교·직원·시스템 권한은 확대하지 않는다.

## 주소와 실제 납품 위치

1. 거래처 주소 또는 상호로 검색하고 결과를 선택한다. 거래처 주소·납품 주소·좌표가 함께 준비된다.
2. 실제 출입구가 다르면 지도 핀을 조정하고 **이 위치로 설정**을 누른다. 좌표의 도로명 주소를 우선하고 없으면 지번 주소를 자동 표시한다.
3. 핀 이동 중에는 기존 주소를 지우고 미확정 상태로 전환한다. 이전 주소로 잘못 저장되지 않도록 확인 전 저장을 막는다.
4. 조회 실패·주소 없는 지점만 선택적 직접 보완 입력을 제공한다. 좌표만 저장할 수도 있으며 임의 주소를 만들지 않는다. 지역명만 반환된 경우 이를 정확한 납품 주소로 간주하지 않는다.

항상 보이는 별도의 실제 납품 주소 입력란은 제거했다. 고급 좌표 입력은 접힌 영역으로 이동했다. 핀을 움직일 때마다 유료 외부 조회를 반복하지 않으며 명시적으로 확인할 때 요청한다. 거래처 주소를 나중에 수정해도 이미 정한 납품 지점과 주소를 덮어쓰지 않는다. 한국어 조합 중 Enter, 오래된 비동기 응답, 닫힌 폼, 저장 중 입력 변경과 응답 유실 재시도를 처리한다.

기존 지역 필드와 데이터 계약은 호환성을 위해 보존한다. DB 마이그레이션이나 기존 거래처 일괄 수정은 없다.

## 상세 화면과 접근성

- 납품 안내와 출입 정보를 가장 먼저 배치하고, 연락처 → 실제 납품 위치 → 조건부 변경사항 → 접힌 기본 정보로 구성했다.
- 밝은 중립색·절제된 민트와 얕은 그림자를 사용한다. 뉴모피즘의 음각 효과는 작은 안내 아이콘 등에만 제한하여 입력 요소와 정보의 구별을 유지한다.
- 연락처가 많으면 대표 연락처 우선으로 2개를 먼저 표시하고 나머지는 펼친다. 대표 번호가 비어 있으면 통화 가능한 다른 연락처를 하단 전화 버튼에 연결하며 실제 대상이 접근성 이름에 표시된다.
- 길찾기·전화·정보 수정은 시트 하단에 고정한다. 최소 50px 터치 높이, 안전 영역, 초점 표시, 모션 감소·강제 색상 대응을 유지한다.
- 지도 오류가 전체 납품 정보나 연락처를 숨기지 않는다. 지도 안의 중복 제목을 제거하고 마커 정보는 키보드로도 접근 가능하다.
- 편집은 상세와 동시에 두 시트를 겹치지 않는다. 수정 중 닫기/뒤로가기 보호, 저장 후 상세 갱신, 인증 상실 시 민감 화면 제거를 유지한다.

프런트엔드 디자인 스킬은 기존 프로덕션의 시각적 일관성과 정보 우선순위를 유지하는 데 적용했다. React 성능 스킬에 따라 별도 UI 라이브러리를 추가하지 않고 거래처·편집기·지도 지연 로딩을 유지했다.

참고: [Toss ListRow](https://tossmini-docs.toss.im/tds-mobile/components/ListRow/list-row-overview/)의 반복 정보 구성, [Toss ConfirmDialog](https://tossmini-docs.toss.im/tds-mobile/components/Dialog/confirm-dialog/)의 행동 위계, [WCAG 비텍스트 대비](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html), [Kakao 좌표→주소 API](https://developers.kakao.com/docs/ko/local/dev-guide#coord-to-address). 외부 컴포넌트 코드를 설치하거나 디자인을 그대로 복제하지 않았다.

## 권한·감사 이력

공유 거래처의 작성 권한만 활성 `delivery`, `sales`, `viewer`, `admin` 직원에게 확장한다. 직원 역할은 `employees.roleScopes`가 기준이며 `authz`에 존재하지 않는 역할 필드를 요구하지 않는다. 관리자는 기존 Google 로그인·관리자 ACL 검증을 그대로 거친다.

- 서버가 로그인 토큰·활성 직원·직원 UID/ID·세션 및 권한 버전을 검증한다.
- 저장 트랜잭션에서 역할 스냅샷과 인증 버전을 다시 검증한다. 중복 요청 재생 시에도 재검증한다.
- 작성자·수정자와 시각은 서버가 결정한다. 클라이언트의 감사 작성자 위조 필드는 거절한다.
- 거래처 변경, 요청 잠금, 감사 로그를 원자적으로 저장한다. 예상 revision 충돌과 요청 재시도 중복을 처리한다.
- 감사 로그에 수정 필드 이름을 남기되 주소·전화·출입 비밀번호의 값은 기록하지 않는다.
- 고객 문서의 직접 클라이언트 쓰기, 감사 로그/요청 잠금의 클라이언트 쓰기는 계속 거절한다. 감사 로그 조회는 관리자 전용이다.
- 운영 App Check, 서버 측 Kakao REST 키, `no-store` 응답을 유지한다. 이번 단계에서 Rules 자체는 변경·재배포하지 않는다.

Firebase 보안 규칙 감사 스킬을 적용한 **이번 거래처 변경 범위**의 평가(앱 전체 무결함 보증이 아님):

```json
{
  "score": 5,
  "summary": "거래처 편집만 활성 직원에게 확장. 서버 기반 신원·역할·세션 재검증과 revision·멱등성·원자적 감사 유지. 직접 고객/감사/요청 잠금 쓰기 차단 유지.",
  "findings": []
}
```

## 검증

운영 거래처를 테스트용으로 만들거나 변경하지 않았다. 쓰기 시나리오는 `demo-onnuriway` 로컬 Firebase 에뮬레이터에서 실행했다.

| 항목 | 결과 |
|---|---|
| 전체 단위 테스트 | 724 통과, 기존 3개 건너뜀 |
| 고객 API·관리자·직원 통합 | 12/12 통과 |
| Firestore·Storage 보안 규칙 | 41/41 통과, 3개 파일 |
| 헤더·관리자 내비게이션 브라우저 | 40/40 통과, 별도 fixture 검증 8/8 |
| 코드 품질 | 전체 ESLint, 앱·Functions TypeScript, diff 검사 통과 |
| 운영 빌드 | Next.js 16.3.2 빌드, PWA 검사, 성능 기준 검사 통과 |

통합 테스트는 직원 실제 등록/수정과 감사 작성자, 관리자 편집, 폐업 상태, 핀 확정 전 저장 차단, 자동 주소와 수동 보완, 수정 내용 보호, 유실 응답 재시도, 충돌·위조·철회된 권한 차단, 최근 5곳·재정렬·로그아웃·오프라인 민감 화면 제거를 포함한다. 최초 새 직원 테스트의 필수 표기와 접근성 label 간 선택자 불일치를 수정한 후 전체 12개를 다시 실행했다. 제품 권한이나 입력 검증을 완화하지 않았다.

320/390/768px 실제 인증 흐름 화면과 320–1280px 헤더를 확인했다. 자동 접근성 검사 위반 0, 관리자 메뉴 9개 접근, 더보기 키보드/Back, 글자 확대 및 고대비를 확인했다. 최종 320px 캡처에서 발견한 하단 비활성 문구 줄바꿈은 좁은 화면의 가로 패딩을 줄여 보완했다.

운영 빌드 최초 JS gzip 139,372 bytes, 기존 공용 CSS gzip 52,020 bytes, 관리자 내비게이션 CSS gzip 1,549 bytes, 영업 workspace JS gzip 12,970 bytes. 거래처 전용 CSS 29,669 bytes/gzip 6,593 bytes, JS gzip 21,533 bytes다. 거래처 전용 CSS와 JS만 이번 상세·입력·직원 기능에 맞게 예산을 각각 gzip 7KiB/22KiB로 명시했다. 로그인·학교·영업 진입에 거래처 CSS가 섞이지 않는 검사를 유지하며 기존 최초 로딩 예산은 완화하지 않는다. PWA 캐시 버전은 `phase34`, service worker 40,660 bytes다.

마지막 CSS 보완 후 전체 lint·운영 빌드·PWA·성능 검사를 다시 통과했다. 실제 BottomSheet와 현재 CSS를 사용하는 독립 브라우저 검사에서 320/360/390px × 정상/미등록 상태 6개 조합을 확인했다. 320px의 세 버튼 너비는 약 97.92/89.03/89.05px, 모두 높이 50px이며 문구 1줄·문서 가로 넘침 0이다.
