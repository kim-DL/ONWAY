# Phase 37 — 거래처 전체보기·전경사진·전화번호

2026-09-06. 기존 밝은 거래처 톤과 직원 권한 경계를 유지한다.

## 구현

- 거래처 홈의 전체보기에서 자치구·지역 → 행정동 → 이름/초성으로 범위를 좁힌다.
  지역별 건수, 선택 초기화, 검색어 삭제, 빈 결과, 재조회 상태를 구분한다.
  목록은 32개씩 펼치며 총수 제한 없이 조회한다. 하단 지역 선택 버튼은 항상 접근 가능하다.
- 검색/전체보기 카드에 실제 납품 좌표 기반 길안내를 추가한다. 카드 선택과 전화/길안내는
  별도 터치 대상이다. 위치가 없으면 임의 주소 검색으로 우회하지 않고 위치 미등록을 알린다.
- 상세 상단에 전경사진을 배치하고 크게 보기·2배 확대·이동·화면 맞춤을 제공한다.
  전체보기→상세→사진에서 뒤로갈 때 부모 화면과 선택한 필터를 보존한다.
- 사진 입력은 직접 촬영/앨범 선택을 분리한다. JPEG/PNG/WebP의 실제 파일 헤더를
  확인해 모바일 앨범의 빈 MIME, application/octet-stream, image/jpg를 안전하게 처리한다.
  손상 파일·변환 실패·연결 실패를 구분하고 동일 업로드 요청의 재시도를 보존한다.
- 거래처 연락처, 학교 영양사·급식실 전화번호는 입력 완료 및 서버 저장 경계에서
  공통 정규화한다. 01012345678→010-1234-5678, 0421234567→042-123-4567.
  서울 02·인터넷 전화·대표번호 등도 처리하되 국제번호/알 수 없는 기존 형식을 임의 변형하지 않는다.
  전화번호 서식만 변경된 것을 실질 정보 변경으로 표시하지 않는다.

## 위치와 기존 자료

등록된 거래처의 지역 정보가 비어 있어도 누락시키지 않는다. 확인 가능한 주소의 자치구를
우선 사용하며, 행정동은 주소 괄호 속 법정동에서 추측하지 않는다. 전체보기에서 기존
납품 좌표를 기존 reverseCustomerLocation API로 조회해 행정동을 보완한다.
동시 요청은 최대 3개, 메모리 캐시와 실패한 항목 재시도, 늦은 응답 폐기를 적용한다.
표시용 보완만 수행하며 운영 DB에 자동 쓰기/일괄 변환하지 않는다.
새 등록·위치 수정 시에는 확인된 지역 정보를 주소와 함께 저장한다.

## 사진 진단과 보안

기존 운영 함수/버킷 설정과 권한은 활성 상태였으며 조사한 로그에서 실제 사진 호출을
찾지 못했다. 따라서 사용자가 겪은 원인을 서버 권한 문제라고 확정하지 않는다.
재현 가능한 모바일 MIME 거부 문제를 수정했고 실제 demo Auth·Firestore·Storage로
업로드→거래처 연결→조회→교체→삭제를 검증했다.

공개 URL/Storage 권한 완화 없이 인증된 사진 요청을 유지한다. 이미지는 메모리에만
표시하고 로그아웃·오프라인 시 폐기한다. EXIF 제거, 서버 이미지 재검증, 업로드와
거래처 연결의 권한/동시성 검증을 유지한다. 서버 오류 로그는 처리 단계와 허용한 코드만
기록하며 파일 경로·주소·토큰·사용자 데이터는 기록하지 않는다.

촬영 capture=environment의 실제 실행 UI는 기기/브라우저에 의존한다. 물리 카메라
실행은 이 환경에서 검증할 수 없다. HEIC는 현재 지원하지 않으며 JPEG 전환 안내를
표시한다. [MDN capture](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Attributes/capture)

## 검증

- 단위 테스트 877 통과, 3 skipped; 93개 파일 통과/1 skipped. 성능 테스트의 기존
  50ms 기준은 유지하며 CPU 경합을 줄인 maxWorkers=2 전체 실행에서 통과했다.
- 앱/Functions TypeScript 및 ESLint 통과.
- production-mode demo Firebase 통합 E2E 16/16 통과: 직원 등록·수정·사진·권한·검색 포함.
- 독립 화면 브라우저 E2E 16/16 통과: 모바일/데스크톱 320·390px, 사진 확대·닫기·
  오프라인 폐기, 전체보기 40개·구/행정동 검색·상세 복귀, axe 위반 0, 200% 글자 확대,
  고대비 키보드 초점 확인. 길안내 글자 대비를 보완하고 긴 지역명은 단어별로 줄바꿈한다.
- 실제 Chrome 합성 자료 70개로 32→64→70 전체 펼치기, 구+행정동+이름 조합 검색,
  하단 필터 복귀, 상세/사진 닫기와 필터 보존 확인. 운영 고객 데이터는 테스트로 수정하지 않는다.
- PWA 아이콘/서비스워커 검증 통과. 새 지연 사진 뷰어도 precache 검사에 포함한다.
- 초기 JS gzip 139,497B, 최대 JS 청크 gzip 66,843B. 기존 초기/학교·영업/공통 CSS
  예산은 그대로 유지했다. 새 거래처 전용 기능은 CSS 47,121B(raw)/9,489B(gzip),
  JS 32,001B(gzip)로 측정하여 해당 지연 기능 예산만 47KiB/9.5KiB/32KiB로 제한했다.
- NodeNext 공용 전화번호 모듈의 .js import를 Next webpack이 .ts 원본으로 해석하도록
  extensionAlias를 추가했다. 실제 .js 우선 및 Functions Node ESM 호환을 유지한다.

uploadCustomerPhoto, getCustomerPhoto만 선택 배포한다. Firestore/Storage 보안 규칙,
인덱스, 기존 사진 정리 작업의 정책은 변경 배포하지 않는다.
Vercel은 기존 `daeins-projects/onnuriway` 연결을

  올바른 버킷 설정 확인. 최근 24시간 사진 서비스의 오류 로그 없음(실제 운영 사진
  쓰기 테스트를 수행했다는 의미는 아니며, 테스트 사진은 demo emulator에만 저장했다).
- Vercel 운영 원격 빌드/TypeScript 통과 및 READY 확인:
  `dpl_APEQTzMbAQhDfWYcpudtoNPDNv18`.
  불변 배포: https://onnuriway-8vkxrlv4z-daeins-projects.vercel.app
  `https://onnuriway.vercel.app` 운영 별칭이 이 배포에 연결됨을 독립 inspect로 확인했다.

  배포별 error 로그 조회 성공, 반환 항목 0. 장시간/실제 직원 활동 모니터링을 대체하지 않는다.

  전체보기 5개 거래처/길안내 5개 확인. 누락 지역의 좌표 조회가 완료되고 행정동 옵션
  보완, 대기/재시도 표시 없음 확인. 이 과정에서 원본 고객 정보·사진·전화번호는
  저장하거나 변경하지 않았다. 새 PIN 로그인 및 실제 카메라/앨범 하드웨어 실행은 별도 범위다.

디자인 스킬은 카드 밀도·정보 위계·명확한 초점/터치 대상에 적용했고, Firebase 검토는
사진 보안 경계와 지역 조회의 읽기 전용 성격을 유지하는 데 적용했다.
