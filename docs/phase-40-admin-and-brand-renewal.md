# Phase 40 — 관리자 화면과 브랜드 모션 정돈

## 변경 범위

- 관리자 운영 개요를 선택한 월의 방문 현황, 학교·직원·위치 검토 수, 자주 쓰는 업무, 최근 변경 순으로 재구성했다. 조회 월의 배정을 현재 월의 배정으로 오인하지 않도록 라벨을 맞췄다.
- 관리자 전용 밝은 슬레이트·블루 표면, 읽기 쉬운 글자, 44px 이상의 주요 조작 영역, 모바일 학교/배정 목록, 직원 저장 버튼과 공통 모달을 적용했다. 데스크톱 메뉴는 세 업무 그룹, 모바일은 기존 5칸과 더보기를 유지한다.
- 직원 등록/보안 작업 모달은 기존 BottomSheet를 재사용한다. native dialog의 배경 접근 차단, 포커스 복원, 키보드 viewport, 저장 중 Escape/PWA Back 보호를 중복 구현하지 않는다.
- 관리자 작업 잠금은 진행 중 메뉴·직원 전환 및 중복 작업을 방지한다. PIN 재발급 결과를 확인할 때까지 유지하며, 재발급·세션 종료의 영향을 먼저 확인한다. PIN 원문은 DTO/로그/저장소에 추가하지 않았다.
- PIN 재발급의 재조회는 결과 확인 후에 실행한다. 다른 관리자가 동시에 직원 이름을 바꿔 현재 검색 결과에서 제외되더라도, 일회성 PIN 확인창이 중간에 사라지지 않는다. 확인 뒤 재조회 및 언마운트 시 작업 잠금도 해제한다.
- 가장 최근 조회 요청만 화면에 반영하고, 실패하면 기존 데이터를 유지하면서 지속 경고와 마지막 서버 확인 시각을 표시한다. 새 NEIS 미리보기/선택 변경 시 위험 승인을 초기화한다.
- 회사명은 기존 글자 크기를 유지한 청록·청회색, 두 굵기의 워드마크로 정돈했다. 4개 원은 학교납품 블루, 거래처 제이드·민트, 영업/홍보 코랄·로즈로 구분한다.
- 모드 테두리는 블루→아쿠아→민트의 연속 그라데이션이다. 클릭 후 남는 focus-within/hover 때문에 정지하던 규칙을 제거했다. 사용자 일시정지, 숨김 탭, reduced-motion, forced-colors 처리는 유지한다.

## 범위와 보존 계약

- 거래처/학교/방문 기록, 저장소 규칙, 서버 역할 및 Google 관리자 승인, 도메인 설정은 변경하지 않았다.
- 관리자 역할 부여 제한, 자기 계정 비활성화 제한, 관리자 PIN 제한, 배정/위치의 expectedRevision 및 감사 사유를 유지한다.
- 운영 데이터에 대한 쓰기 검증은 하지 않는다. 상호작용 검증은 합성 데이터, 서비스 검증은 demo-onnuriway의 로컬 에뮬레이터를 사용한다.

## 스타일·성능

기존 전역 관리자 스타일 약 47KB(원본)를 제거하고 지연 로드되는 관리자 모듈로 교체했다. 직원 화면에 관리자 CSS가 섞이지 않는 것을 배포 빌드 manifest로 검증한다. 공용 학교 선택기 스타일은 그대로 둔다.

관리자 내비게이션과 전체 UI CSS가 하나의 청크로 묶이므로 성능 게이트는 관리자 UI를 합산한다. 기존 초기 JS/거래처/영업 제한은 유지하며, 비관리자 CSS 제한은 275KiB→235KiB(raw), 52KiB→44.5KiB(gzip)로 낮췄다. 관리자 UI의 별도 상한은 64KiB/10KiB다. 관리자 지연 자산의 PWA precache 포함도 확인한다.

측정: 초기 JS gzip 139,492B, 비관리자 CSS raw 234,793B/gzip 45,103B, 관리자 CSS raw 64,298B/gzip 9,362B. 전체 관리자 CSS를 처음 관리자로 진입할 때만 받는 비용이며 초기 로그인에 추가되지 않는다.

## 검증

- 전체 단위 테스트: 939 통과, 기존 3건 건너뜀.
- 관리자 저장/모달/요청 역전/작업 잠금/NEIS/PIN 안전 회귀 및 기존 관리자 계약 통과.
- 관리자 에뮬레이터 게이트 2회 통과: 직원 생성, PIN 교체·이전 PIN 차단, 세션/권한 버전, Google 관리자 승인, 감사 이력.
- 실제 React 관리자 화면: 320/390/900/1280px, 200% 글자, 44px 조작 영역, axe, 모달 포커스/뒤로가기/오류복구를 합성 데이터로 검증.
- 세 모드 헤더·원 팔레트·연속 모드 전환·명시적 정지·탭 숨김/복귀·reduced-motion 회귀 검증.
- 관리자·헤더 브라우저 검증 68건 통과(검색 중 PIN 결과 확인 전후 이름 변경 시나리오 포함). 좁은 화면·200% 글자 및 동기화 키보드/접근성 검증은 추가 20회 반복 통과했다. 이전 단일 실행의 설정 가로 넘침은 현재 코드에서 재현되지 않았으며, 재발 시 요소와 좌표를 남기도록 기존 테스트 진단을 보강했다.
- 직원용 거래처 UI 회귀 32건 통과: 검색·최근 카드·전체 보기·필터·사진·출입 비밀번호·200% 글자·접근성.
- lint, 앱/Functions TypeScript, production build, 성능/PWA 게이트 검증.

휴대폰 실기기의 삼성 키보드/PWA 제스처 및 실제 운영 관리자 계정에서의 최종 육안 확인은 자동화 검증과 별개다. 검증을 위해 운영 직원이나 PIN을 생성·변경하지 않는다.
