# Phase 43 — 학교 납품 현장정보 리뉴얼

## 구성

- 학교명·주소만 남긴 간결한 헤더. 목록에서 쓰던 초등(책), 중등(학교 건물), 고등(학사모) 마크를 재사용한다. 중복 행정구/학교급, 데이터 완성률 배지는 제거한다.
- 검수시간 → 급식실 위치/출입구/동선 → 대차·엘리베이터 → 작성된 현장 참고 → 전화 연락처를 한 카드에 통합한다. 진한 4칸 요약, 01–04 하위 카드, 중복 학교 기본정보 카드는 제거한다.
- 시작/종료만 있는 검수시간은 각각 ‘부터/까지’로 구분한다. 미등록 정보는 확인된 상태로 표시하지 않는다.
- 차량·하역, 계단 입력 UI는 제거한다. 전체 수정 patch는 vehicle을 보내지 않으며, equipment의 기존 stairsRequired 값은 그대로 보존한다. 저장 API/스키마/데이터베이스는 변경하지 않는다. 완성률은 폐기 필드도 포함하므로 이 화면의 준비 상태로 사용하지 않는다.
- 실제 연락처는 전화 링크로 유지한다. 현장정보가 아직 없어도 학교 대표 전화는 표시한다.
- 사진에 기본 문구나 조작 버튼을 겹치지 않는다. 사진 아래에 위치명, 직접 작성한 캡션, 크게 보기·교체·삭제를 둔다. 비어 있는 슬롯 수/준비 완료 배지는 제거한다. 빈 칸은 모바일에서 짧은 행으로 보인다.
- 14px 섹션, 12px 사진 카드, 8px 버튼으로 곡률을 낮춘다. 흰색에 푸른 배경이 스미는 상단 틴트는 유지한다. 터치 영역은 44px 이상, 긴 내용은 줄바꿈, 포커스 표시와 시스템 고대비 지원을 유지한다.
- 기존 사진 업로드·교체·삭제·복구·확대 및 부드러운 닫기 효과를 유지한다. 외부 크게 보기 버튼도 실제 사진 영역을 확대 시작점으로 사용한다.

## 참고 및 적용

- [Toss TDS ListRow](https://tossmini-docs.toss.im/tds-mobile/components/ListRow/list-row-overview/): 주요 정보와 보조 정보를 분리하고 짧은 행으로 읽는 구조를 참고했다. 라이브러리나 디자인 파일을 가져오지 않았다.
- [Material 목록의 조작 요소](https://m1.material.io/components/lists-controls.html): 주요 콘텐츠와 보조 행동을 별도의 조작 대상으로 구분하는 원칙을 사진 하단 도구에 적용했다.
- frontend-design 스킬로 기존 밝은 톤에 맞춰 정보 우선순위·밀도·곡률을 재설계했다. React 성능 가이드에 따라 기존 아이콘/지연 로딩을 재사용하고 새로운 라이브러리나 요청을 추가하지 않았다.

## 성능 및 안전

- 폐기된 납품·사진 전역 스타일 약 15KB를 제거했다. 편집 폼, 사진 업로더/뷰어, 다른 모드의 공용 규칙은 유지한다.
- 새 갤러리 CSS는 사진이 필요할 때만 로드된다. Next가 사진 모핑·학교 뷰어·갤러리 스타일을 묶어 사진 전용 청크가 6,711B raw / 1,928B gzip가 된다. 기존 두 사진 컴포넌트만 소유하고 로그인에서는 로드되지 않는 조건을 유지한다.
- 사진 청크의 개별 한도를 재분류하되, 기존 학교/공용 CSS와 사진 CSS의 합계에는 이전 합산 한도 238.5KiB raw / 45.625KiB gzip를 추가해 전체 예산이 증가하지 않게 했다. 초기 JS·다른 기능 예산은 그대로다.
- 생산 빌드 및 PWA 캐시 검사, 전체 단위 테스트(983 통과/환경 전용 3 건너뜀), 앱/Functions 타입 검사, ESLint 검증.
- 브라우저는 실제 컴포넌트에 합성 데이터와 메모리 저장소를 연결한다. 직원 PIN 제출이나 운영 데이터 쓰기는 하지 않는다. 인증 에뮬레이터 테스트의 기존 선택자도 갱신했으나 이번에는 해당 에뮬레이터 묶음을 별도로 실행하지 않았다.
