# Plan

기존 급식길의 화면·인증·데이터를 유지하면서 정적 프런트엔드를 Firebase Hosting으로 옮긴다. 인증서와 기존 기능을 확인한 뒤 onnuriway.com의 DNS만 전환한다. 재고는 기존 영업 추천상품과 분리하고, 수량 정확성을 먼저 확보한 후 기존 디자인 시스템 안에 네 번째 모드로 통합한다.

## Scope

- In: Firebase Hosting, 동일 도메인과 PWA 유지, 기존 로그인·지도·사진 검증, 재고 제품/로트/수량/실사/이력/권한과 모바일 UI.
- Out: 네임서버 변경, Vercel 프로젝트 삭제, 기존 데이터 이전/삭제, 영업 샘플 전달 자동 출고, 발주·회계·바코드 연동, 새 인증 역할.

- [x] Firebase 기본 주소에서 기존 기능을 검증하고 사용자 지정 도메인의 인증서를 사전 준비한다.

## Architecture decisions

- 기존 `onnuriway`의 Firestore Standard/Native, 서울 리전을 재사용한다. 이미 Blaze 연결 상태이며 별도 요금제 변경은 하지 않는다.
- `companies/onnuri/inventory*`를 사용한다. 기존 최상위 영업 `products`와 섞지 않는다.
- 상품 정보와 수량 변경을 분리하고, 유통기한별 로트와 보관 장소별 수량을 보존한다.
- 모든 수량 변경은 서버에서 원자적으로 처리한다. 예상 revision·지속적인 요청 식별자·불변 이력으로 충돌과 중복 반영을 차단한다.
- 기준 단위와 환산을 검증한다. 이미 수량 이력이 있는 상품의 단위 변경으로 과거 값이 재해석되지 않도록 한다.
- 기본 실사일은 한국 시간 금요일이다. 회차 ID와 확인 이벤트로 완료를 판단하며, 미입력과 확인한 0개를 구분한다. 확인 후 수량 변동도 구분한다.
- 활성 직원은 조회, delivery/sales/admin은 제품 등록·수량 작업·실사, admin은 설정·비활성·삭제를 수행한다. viewer는 조회 전용이다.
- 잔량이나 이력이 있는 상품은 영구 삭제하지 않는다. 비활성/보존 상태로 감사 가능성을 유지한다.
- 오프라인이나 서버 응답 전에는 저장·실사 완료를 표시하지 않는다.
- 사진은 제품별 1개이며 기존 촬영/앨범·안전 변환·비공개 조회 흐름을 재사용한다.
- 목록 전체의 주기적 재조회 대신 필요한 요약을 불러오고 로트/이력은 상세에서 조회한다.
- 기존 폰트·은은한 배경·절제된 카드·고정 하단 동작을 재사용한다. 4개 모드는 모바일에서 충분한 터치 폭을 확보한다.
- 미검증 재고 기능은 `NEXT_PUBLIC_ENABLE_INVENTORY` 플래그로 기존 운영 흐름에서 숨긴다.

## Open questions / verification gates

- 도메인의 현재 DNS와 Firebase 인증서 발급 상태는 실제 관리 화면에서 확인한다. 인증서 준비 전 운영 DNS를 바꾸지 않는다.
- 사용자 실데이터를 자동 생성하지 않는다. 최초 상품과 단위는 운영자가 입력한다.
- 휴대폰 카메라·앨범·키보드·PWA 설치는 데스크톱 검증과 구분하여 보고한다.

## 재고 운영 시작 안내

1. **기준 단위부터 확인:** 개·봉·팩처럼 실제로 세는 가장 작은 단위와 박스당 수량을 정한다. 예를 들어 1박스=8봉이면 2박스+3봉은 19봉으로 저장된다. 수량 이력이 생긴 뒤에는 과거 기록을 보호하기 위해 단위와 박스 구성을 바꿀 수 없다. 수량은 정수이며 소수 중량이 필요하면 g 등 작은 기준 단위를 사용한다.
2. **품목 등록 후 첫 입고:** 제조사·규격·원산지·보관 장소·메모·사진을 등록하고, 입고에서 수량과 유통기한을 입력한다. 같은 상품도 유통기한이 다르면 새 묶음으로 입고한다.
3. **주간 실사:** 냉장·냉동1·냉동2·샘플을 각각 확인한다. 수량이 같아도 `수량 일치 · 실사 완료`를 눌러야 이번 회차 확인이 된다. 확인 뒤 해당 장소의 재고가 변하면 `변동 후 미확인`으로 바뀐다. 다른 장소만 바뀌면 이미 확인한 장소까지 취소하지 않는다.
4. **날짜와 필터:** 기본 실사일은 금요일이다. 관리자는 재고 설정에서 요일과 임박 기준일을 바꿀 수 있다. 요일 변경은 진행 중인 회차를 지우지 않도록 다음 회차부터 반영한다. 날짜를 모르는 상품은 임박 필터의 결과만으로 안전하다고 판단하면 안 된다.
5. **연결과 새로고침:** 다른 직원의 변경은 새로고침으로 확인한다. 저장 충돌 시에는 최신 수량을 확인한 뒤 다시 입력한다. 오프라인에서는 현재 열린 창의 입력만 메모리에 유지하며 자동 저장하지 않는다. 창·페이지를 닫으면 입력이 사라질 수 있다.
6. **권한과 이력 보존:** 조회 전용 직원은 수량을 바꿀 수 없다. 비활성화·삭제·설정은 관리자 작업이다. 재고가 남아 있으면 비활성화할 수 없고, 수량 이력이 있으면 삭제 대신 비활성화한다.

처음에는 실제 상품 1개로 단위·첫 입고·실사·출고를 확인한 뒤 품목을 늘린다. 갤럭시의 직접 촬영·앨범 선택·키보드·설치된 PWA 복귀는 데스크톱 자동 검증과 별도로 확인한다.
