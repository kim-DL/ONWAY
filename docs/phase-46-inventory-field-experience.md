# Phase 46 — 현장 재고 UX와 모드 선택

2026-09-13. 기존 급식길의 밝고 절제된 톤을 유지하고, 4개 업무 모드와 실제 재고조사 흐름을 다듬는다.

## 사용자 확정사항

- 휴대폰에서는 로고·회사명 옆에 `모드 전환 / 현재 모드 ▾` 버튼을 두고 넓은 선택창을 연다. 선택 기능의 발견성과 전환 모션을 함께 확보한다.
- 신규 상품의 사진·제품 정보·초기 수량·첫 유통기한을 한 화면에서 입력하고 한 번에 저장한다.
- 유통기한 임박 기준은 **D-100일**. 기한이 지난 유효 재고도 임박 필터에 포함한다.
- 미완료 테두리 강조는 **지정된 재고조사일에만** 적용한다. 해당 회차 확인 완료는 초록색, 이후 수량이 변한 상품은 ‘변동 후 미확인’이다.

## 참고와 판단

`C:/Users/HOME/Desktop/레퍼런스/`의 5개 화면에서 사진·상품명·수량의 우선순위, 명확한 창고 구역 선택, 간결한 상품 등록 순서를 참고했다. 예전 작업 `UI/UX 개선 아이디어`, `Redesign products zone buttons`, `Add cache layer for products fetch`에서 초기 수량 필수, 박스·낱개 직접 입력, 상태 테두리, 한국어 초성 검색 선호를 확인했다. 과거의 입출고 자동 실사 처리나 유령 재고 자동 0처리는 가져오지 않았다.

- [eBay segmented button](https://playbook.ebay.com/design-system/components/segmented-button): 긴 모드 이름을 좁은 분할 버튼에 강제로 압축하지 않고 선택창으로 전환한다.
- [WAI modal dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/): 키보드 포커스, 닫기, 이전 화면 복귀를 보존한다.
- [WCAG Use of Color](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color): 상태는 색상만이 아니라 텍스트·아이콘·접근 가능한 설명으로 전달한다.

## 구현

### 모드 선택

- 900px 이하: 회사명 옆에 모드 전환 버튼. 현재 모드의 아이콘·색·이름과 펼침 화살표를 함께 표시한다.
- 900px 초과: 기존 분할 선택을 유지한다. 권한이 없는 모드는 표시하지 않는다.
- 선택창은 넓은 4개 행, 현재 선택 표시, 짧은 순차 진입 모션으로 구성한다.
- 기존 BottomSheet의 닫기 경로를 재사용해 Back 기록을 먼저 소비한 후 모드를 바꾼다. 새로운 별도 history 체계를 만들지 않는다.
- `prefers-reduced-motion`과 키보드 포커스를 지원한다.

### 목록과 상세

- 64px 제품 썸네일, 큰 수량, 상품명·제조사·규격, 날짜·실사 배지를 간결한 카드에 배치한다.
- 썸네일은 화면에 가까운 항목만 요청한다. 비공개 사진을 공개 URL이나 영구 브라우저 캐시에 저장하지 않는다.
- 진행 영역 높이를 줄이고, `임박 상품만 · D-100일`, `미확인만`, 검색을 함께 제공한다.
- 상세는 사진/현재 수량, 제품 기본 정보, 유통기한별 수량, 보조 작업으로 정리한다. 입고·출고·수량 확인은 하단 고정 작업 영역에 둔다.
- 비활성 상품은 실사 진행·미확인 필터·테두리 강조에서 제외한다.

### 등록과 수량 처리

- 사진은 촬영/앨범 경로를 유지하면서 작은 미리보기 영역을 사용한다.
- 신규 등록에 초기 수량 1 이상이 필요하다. 날짜를 바로 입력하거나 ‘미확인/해당 없음’을 명시적으로 선택할 수 있다.
- 제품, 첫 재고, 입고 이력, 사진 연결, 감사 기록, 재시도 영수증을 같은 서버 트랜잭션으로 기록한다. 네트워크 응답이 불확실해 재시도하더라도 중복 입고하지 않는다.
- 기존 제품 수정에서는 초기 재고를 전달하지 않는다. 구버전 클라이언트의 0재고 품목 생성 계약은 호환 유지한다.
- 재고 날짜가 하나면 불필요한 선택을 생략한다. 여러 날짜는 빠른 날짜부터 수량과 함께 선택한다.
- 실물 확인에는 장부 합계·실측 합계·차이를 표시한다. 수량이 다르면 사유가 필요하다. 입출고는 실사 완료로 자동 처리하지 않는다.

## 검증 / 출시

테스트 상품과 사진은 전용 `demo-inventory-e2e` 환경에서만 사용했다. 운영 상품 데이터에는 시험용 제품을 추가하지 않았다.

- 전체 단위 테스트 1,215개 통과. 통합 실행이 필요한 9개는 일반 단위 실행에서 의도적으로 제외된다.
- 헤더 브라우저 회귀 44개 통과: 320/360/390/768/1280px, 권한별 모드, 선택창/Back/Escape/연속 닫기/포커스 복구.
- 실제 정적 빌드·Auth/Functions/Firestore/Storage 에뮬레이터 업무 흐름 5개 통과: PIN 로그인, 사진과 초기 D-100 재고 등록, 임박 필터, 두 날짜 실사, 특정 날짜만 출고, 장소 이동, 사진 교체/제거, 읽기 전용과 권한 회수, 오프라인 초안/명시적 재시도, 1,000개 목록/60개씩 추가 표시.
- 같은 에뮬레이터 수명 안에서 Firestore 실제 통합 검사 6개 별도 통과. 초기 재고 원자 저장, 동시 재시도, 실패 시 전체 롤백을 포함한다.
- 브라우저 검증 후 신규 등록 ‘필수’ 표기의 수직 정렬을 보완하고, 동일한 썸네일 CSS를 기존 재고 스타일 모듈로 합쳤다.
- 이력 조회의 첫 페이지/추가 페이지 재시도, 늦은 목록 응답과 저장의 경합, 접근 가능한 카드 상태 설명을 추가로 보완했다. 조회 중 성공한 변경만 임시 메모리로 보호하며 다음 새 조회는 서버 응답을 따른다.
- 운영 관리자 화면에서 임박 기준을 7일에서 **100일**로 저장하고 금요일 설정을 유지했다. 감사 이력을 포함한 기존 설정 API를 사용했다.
- `saveInventoryProduct`, `getInventoryContext`, `recordInventoryCount`, `updateInventorySettings` 4개만 선택 배포했고, 모두 Seoul `ACTIVE` 상태를 확인했다. 인증/사진/나머지 기존 업무 함수와 보안 규칙, 도메인 설정은 변경하지 않았다.

### 최종 운영 배포

- 2026-09-13 00:55 전후 Firebase Hosting `onnuriway` 운영 배포 완료. 기존 도메인·DNS·인증 설정을 유지했다.
- 최종 전체 단위 1,215개, TypeScript, ESLint, diff 검사 통과. 최종 헤더 CSS 정리 후에도 헤더 브라우저 44개와 관련 단위 21개를 다시 통과했다.
- PWA·정적 Hosting·성능 게이트 통과. 최초 JavaScript gzip 140,744B, 재고 지연 로딩 JS 20,492B, 재고 CSS 4,084B로 기존 4KiB 제한을 유지한다. 재고 CSS는 로그인이나 다른 업무 모드에 로드되지 않는다.
- 새 모드 선택 UI의 공통 스타일은 구형 덮어쓰기 규칙 제거로 약 191B를 회수했다. 기존 개별 공통 CSS·사진·초기 JS 한도는 그대로 두고, 공통+학교사진 합산 한도만 신규 선택 UI를 위해 512B 추가했다. 최종 합산은 47,175B / 47,232B다. 기능과 접근성을 삭제해 용량을 맞추지 않는다.

- 운영 worker SHA-256: `cc21596587f131c62bb80ab92ca9d48380ac6e8885c0084a7ad06b9ca9c5ec91`.
- 실제 운영 관리자 세션에서 ‘업데이트’ 안내를 눌러 PWA 업데이트, 로그인 유지, 새 재고 화면, D-100 표시를 확인했다. 이 과정에서 경고·오류 로그는 없었다.

실제 갤럭시의 카메라/앨범 선택기·키보드·설치 PWA 사용감은 데스크톱 및 에뮬레이터 검사와 구별하며, 휴대폰 확인이 남아 있다. 운영 PIN 로그인은 앞선 사용자 확인이 있고, 이번 새 직원 모드 흐름의 PIN 검증은 실제 Auth 에뮬레이터에서 수행했다. 운영 직원 PIN을 임의로 발급하거나 추측하지 않았다.
