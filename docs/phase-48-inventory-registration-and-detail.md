# Phase 48 — 재고 등록·상세와 직원 현장 권한

## 적용 범위

2026-09-13의 등록/상세 개선 10개 항목과 추가 요청인 **재고 사진 촬영 전용**을 함께 적용한다. 기존 급식길의 은은한 배경, 보관 장소, D-100 임박 기준, 기준 단위 수량, 실사일 강조 정책을 유지한다. 거래처·학교의 앨범/파일 선택 기능은 변경하지 않는다.

- 하단 내비게이션의 실사 진입을 제거한다. 재고 실사 기능은 품목의 ‘수량 확인’에서 계속 사용할 수 있다.
- 등록 화면은 사용자 제공 레퍼런스처럼 촬영 행 → 제품명·구역 → 제조사/원산지 → 규격/단위 → 유통기한 → 초기 수량 순서로 구성한다. 초기 재고를 함께 저장하며 박스 환산 입력은 다시 넣지 않는다.
- 유통기한은 `YYYY-MM-DD` 직접 입력과 별도 달력 선택을 함께 제공한다. 8자리 숫자를 자동 구분하고 실제로 없는 날짜와 잘못된 윤년은 거절한다. 날짜 미확인/해당 없음은 별도 선택으로 유지한다.
- 제품 등록·정보 수정의 사진은 후면 카메라 촬영 입력 하나만 제공한다. 앨범/파일 선택 버튼을 제거하고 재촬영·제거를 제공한다. 브라우저의 `capture="environment"`를 사용하며, 촬영 화면의 실제 실행은 휴대폰 브라우저가 담당한다. 업로드 파일의 촬영 출처를 증명하는 보안 기능은 아니다.
- 상세 제목은 굵게, 제품 정보는 중앙 정렬과 반투명 구분선으로 구성한다. 중복 네 구역 탭은 제거하고 여러 보관 장소가 실제로 필요한 제품만 상단의 단일 선택기를 사용한다.
- 비어 있는 재고 안내와 공간을 제거하고 날짜별 수량 행의 높이를 줄인다. 날짜·수량의 위계를 높이고 임박 재고에만 D 배지를 표시한다.
- 품목 정보 수정/입출고·실사 기록 및 출고/입고/조정/수량 확인은 같은 고정 하단 영역에 배치한다.
- 제품 사진은 기존 학교·거래처의 모핑 동작을 공유하는 지연 로딩 뷰어로 확대한다. 2배 확대/전체 보기, 닫기, 뒤로가기, 동작 감소 환경을 지원한다.
- 저장 성공 안내는 약 3.4초 뒤 사라진다. 같은 문구가 연속 발생하면 새 저장 기준으로 시간을 다시 계산하며 오래된 타이머가 새 안내를 지우지 않는다.

## 직원 권한과 데이터 보존

이번 요청은 Phase 47의 관리자 전용·수량 0·이력 없음 조건을 명시적으로 대체한다.

- 기존 재고 쓰기 권한을 가진 직원이 비활성화·재활성화·삭제할 수 있다. 읽기 전용 직원은 거절하며 실사 요일 등 운영 설정은 계속 관리자 전용이다.
- 수량이 있거나 입출고 이력이 있어도 처리할 수 있다. 삭제는 제품을 목록에서 제외하는 tombstone이며 수량, 날짜별 재고, 거래 이력, 사진 참조를 파괴하지 않는다. 삭제된 제품의 새로운 상세/사진 접근은 거절한다.
- 직원·시각·제품명·단위·전후 상태·구역별 수량 스냅샷을 같은 트랜잭션의 감사 기록으로 남긴다. 감사 저장 실패, 권한 철회, 동시 수량 수정 충돌은 전체 롤백/안전 재시도로 처리한다.
- 관리자 감사 기록은 직원 이름과 한글 작업명을 표시하며 제품명 및 전후 상태/수량을 읽기 쉽게 보여준다. 기존 관리자 API의 strict 응답 형태는 유지한다.
- 유통기한 변경 사유 입력은 제거한다. 기존 날짜/새 날짜와 처리 직원은 자동 기록한다. 입출고 조정·삭제의 처리 사유는 이 요청과 다른 기능이므로 유지한다.
- 감사 사유는 허용 길이 2,000자까지 보존한다. 초과값은 조용히 자르지 않고 저장을 거절한다.
- 인증·App Check·활성 직원·권한 버전의 기존 서버 검사, revision 충돌 방지, idempotency receipt를 유지한다. Firestore/Storage 보안 규칙과 인덱스는 변경하지 않는다.

## 디자인·접근성

`frontend-design` 기준을 기존 앱 디자인에 맞춰 적용했다. 간격을 줄이되 주요 터치 영역 44px 이상과 고정 버튼 접근을 유지한다. 달력은 [WAI-ARIA 날짜 선택 대화상자 예제](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/examples/datepicker-dialog/)를 참고해 방향키·월/연도 이동·선택 상태·포커스 복귀를 구현했으며 기존 BottomSheet의 모바일 뒤로가기 정책을 재사용한다. 사진 뷰어도 기존 확대/닫힘 로직을 재사용해 새로운 애니메이션 라이브러리를 추가하지 않았다.

## 검증

- 최종 전체 단위: **1,314개 통과**, 별도 통합 환경용 12개는 일반 실행에서 제외.
- 정적 프로덕션 UI E2E: **7/7 통과**. 직원 PIN → 촬영 입력 → 첫 수량 등록 → 날짜 입력/달력/Back → 입출고/조정/실사 → 사유 없는 날짜 수정 → 사진 확대/Back → 비활성화/복구/삭제 → 감사 이력·알림 소멸을 검사했다. 읽기 전용·권한 철회·오프라인 초안·여러 구역·1,000개 목록도 포함한다.
- 실제 Firestore 에뮬레이터 통합: **9/9 통과**. 상태 변경 후 수량·이력 보존, 원자 저장, 충돌, 롤백 및 재시도를 확인했다.
- 사진 브라우저 회귀: **16개 통과**. 재고는 카메라 입력 하나, 거래처는 기존 앨범/파일 선택을 유지한다.
- 360/768/1280px 화면을 확인했다. 상세 보조 버튼은 스크롤 시 고정되며, 촘촘한 카드에서도 가로 넘침과 버튼 중첩이 없다.
- ESLint, 앱/Functions TypeScript, 정적 운영 빌드, PWA 및 Hosting 빌드 검사 통과.
- 검증은 격리 환경에서 수행했고 운영 재고·사진·이력을 테스트 목적으로 생성/수정/삭제하지 않았다. 브라우저 테스트의 파일 주입 성공을 Galaxy S20+ 실제 카메라 실행 검증으로 간주하지 않는다.

## 배포

기존 Firebase `onnuriway`, Firestore Standard/Seoul과 도메인을 유지한다. 재고 callable 13개와 관리자 조회 `getAdminWorkspace`/`listAdminAuditLogs`를 먼저 배포한 뒤 Hosting을 배포한다. 예약 사진 정리, 타 모드 함수, 규칙, 인덱스, 유료 최소 인스턴스 설정은 배포 범위에 포함하지 않는다.

## 번들 예산

재고 전용 CSS는 신규 달력과 등록/상세 디자인을 포함해 23,026B raw / 5,485B gzip이다. 이 지연 로딩 기능의 한도만 20→23KiB raw, 4→5.5KiB gzip으로 조정했다. 재고 JS는 기존 24KiB 한도 안에서 workspace 20,509B + 확대 뷰어 2,231B = 22,740B gzip이다. 초기 JS 140,762B, 거래처 JS 35,876B이며 초기/학교/영업/거래처 한도는 변경하지 않았다. 신규 패키지는 없다.

공유 사진 CSS 6,711B raw / 1,928B gzip은 그대로다. 사진 확대 경계만 고객/학교/재고 세 곳으로 명시하며 공유 파일을 중복 합산하지 않는다. 재고 CSS/JS가 로그인이나 다른 모드에 유입되지 않는 검사를 추가했다. 정적 파일 98개, precache 69개이며 성능 게이트 통과.
