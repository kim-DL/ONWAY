# 명세서·손글씨 사진 인식과 Decisions 비교

> 이후 사용자 요청으로 Decisions를 제거하고 모델 비용·속도를 다시 비교했다. 아래는 당시의 이력이며 현재 구현은 [Responses 최적화 기록](photo-response-optimization-20261108.md)을 따른다.

2026-11-08 로컬 구현과 실제 API 비교를 완료했다. 운영 앱과 Functions는 배포하지 않았다. 기존 운영 재고·입출고·납품 기록에 시험 데이터를 쓰지 않았다.

## 변경한 동작

사진 일괄 등록은 Responses로 이름·날짜·이름 위치를 읽는다. 새 일괄 인식 모델은 `gpt-6-astra`, reasoning `low`다. 기존 단일 명세서 API의 모델은 유지한다. 이미지와 위치별 잘라낸 영역은 RAM에서 처리하고 Firebase Storage·Firestore에 사진을 저장하지 않는다.

등록된 상호가 쉼표·세미콜론으로 병기된 경우 각 이름도 정확 일치 대상으로 사용한다. 예를 들어 `더푸드 , 동해냉동 , 푸드원`의 `더푸드`는 등록된 이름이다. 공백으로 임의 분리하지 않고, 괄호가 있는 상호는 지점 혼동을 막기 위해 분리하지 않는다. 같은 이름을 가진 거래처가 여러 곳이거나 날짜·주소·기억한 줄임말이 충돌하면 확인 대상으로 남긴다. 이 경로의 출처는 `registered_name`이다.

그다음 연결되지 않은 항목 중 조건에 맞는 것만 `gpt-6-luna` Decisions에 보낸다. 원본과 추정한 이름 영역, 제한된 후보 상호를 함께 비교한다. 후보에는 판독 불가 선택지를 포함한다. 문자 확인 predicate와 후보 선택 choice를 한 번의 요청에서 평가한다. 확률 0.98, confidence 0.9, 후보 간 격차 0.8, 문자 확인 확률 0.99를 모두 만족해야 자동 연결한다. 이 값은 보수적인 초기 기준이며 한 장의 사진으로 보정된 정확도 보장이 아니다.

한 글자 줄임말, 날짜 확인 필요, 주소 충돌, 비활성·변경된 별칭, 같은 상호의 여러 거래처, 잘린 후보 목록은 자동 판단에서 제외한다. `rawName`은 원래 OCR 결과로 유지하고 AI가 줄임말을 자동 학습하지 않는다.

외부 API는 Firestore transaction 밖에서 호출한다. 최종 transaction에서 권한·날짜·전체 거래처 및 직원별 별칭 상태를 다시 확인한다. API 실패나 유효하지 않은 응답이면 기존 정확 일치 결과와 확인 절차를 유지한다. Decisions는 20초 제한이며 내부 자동 재시도를 하지 않는다.

## 비교 조건

- 사용자가 제공한 실제 손글씨 원본 한 장을 사용했다. 12줄이다.
- `용`, `승`은 사용자가 글자와 의미를 확인했다. `승`을 `송`으로 읽으면 오답으로 계산했다.
- 기존 방식은 직전 로컬 일괄 등록 구현의 Responses Luna 요청과 정확 일치 matcher를 고정한 것이다. 현재 배포된 단일 명세서 기능과의 비교는 아니다.
- 동일한 브라우저 사진 준비 코드, 이미지, 223개 활성 거래처의 읽기 전용 snapshot, 날짜, 빈 별칭 목록을 사용했다. 정답을 모델 프롬프트에 넣지 않았다.
- 최종 구성으로 기존·개선 방식을 번갈아 각각 5회 호출했다. 60개는 서로 다른 표본이 아니라 같은 12줄을 5회 읽은 결과다.
- 시간은 로컬 서버 이미지 처리부터 실제 OpenAI 응답·연결 판정까지다. 휴대폰 촬영, Firebase 업로드 네트워크, Callable cold start, Firestore commit은 포함하지 않는다.
- 입력 사진·요청·코드 hash 및 각 응답의 시간, HTTP 상태, 사용 토큰, OCR, 후보, 판정은 ignored `output/decisions-comparison/`에 보관했다. API 키는 보관하지 않았다.
- API 추론이 대부분의 시간을 차지한다. 동일 사진 반복으로 prompt cache 영향을 받으며 실제 현장 시간의 보장은 아니다.

## 최종 결과

| 지표 | 기존 Responses 단독 | 개선 Responses + 등록명 분리 + Decisions |
| --- | ---: | ---: |
| 글자와 이름 전체가 정확한 줄 | 45/60, 75.0% | 55/60, 91.7% |
| 사진 한 장의 자동 연결 | 1~2곳, 평균 1.2곳 | 매회 5곳 |
| 확인할 항목 | 10~11곳, 평균 10.8곳 | 매회 7곳 |
| 잘못된 자동 연결 | 0/6 | 0/25 |
| 처리 시간 중앙값 | 7.95초 | 12.75초 |
| 처리 시간 범위 | 6.01~10.59초 | 11.91~14.70초 |
| HTTP·네트워크 실패 | 0 | 0 |
| Decisions만으로 추가 연결 | 해당 없음 | 0곳 |

자동 연결 5곳은 더푸드, 나누리, 자연유통, 금필, 이레다. 나누리·금필은 전체 이름 정확 일치이고 나머지는 병기된 등록 이름의 정확 일치다. 상호 대응 평가는 제공된 사진과 등록 상호를 대조한 결과이며 실제 배송 의도를 별도 현장 확인한 것은 아니다. `용푸드`라는 정식 이름은 이 snapshot에 없어 그 항목의 대상 ID를 추측하지 않았다.

개선 방식은 `용`과 `금필`을 5회 모두 정확히 읽었다. `승`은 5회 모두 `송`으로 읽어 여전히 확인이 필요하다. 두 방식 모두 한 글자를 임의 거래처로 자동 연결하지 않았다.

Decisions 판단 시간 중앙값은 0.74초이고 범위는 0.61~0.95초다. 정상 응답은 받았으나 자동 연결 기준을 넘지 못했다. 따라서 자동 연결 증가를 Decisions의 효과로 설명할 수 없다. 이번 사진에서 확인된 효과는 모델 변경과 등록명 분리에서 나왔다. 추가 API·이미지 입력으로 토큰 사용도 증가했다. 최종 1회당 입력 토큰 중앙값은 3,318에서 11,058로 늘었으며 모델 단가와 cache 요율이 달라 이 비율이 금액 비율은 아니다.

## 탐색과 최종 비교의 구분

개발 중 `original` detail, 겹치는 이미지 분할, Sol·Astra, Decisions 전체 이미지·분할·이름 영역·질문 개선을 실제 사진으로 시험했다. 상세 해상도나 분할만으로 안정적인 개선을 보지 못해 Responses는 원본 한 장을 사용한다. 잘라낸 영역은 Decisions 확인에만 사용한다.

중간 구성의 별도 5회 비교는 기존 49/60, 개선 55/60이었고 개선 자동 연결은 2곳이었다. 최종 구성의 5회와 섞지 않는다. 같은 사진의 반복과 개발 중 조정이 있으므로 이 결과를 새로운 손글씨·다른 촬영 조건 전체의 정확도로 일반화할 수 없다.

최종 반복 실행 중 독립 검토에서 발견한 기존 invoice 별칭과 병기 상호 충돌 방어를 추가했다. 비교는 시작 시 로드한 matcher로 수행됐고, 빈 별칭인 비교 입력에는 이 조건이 실행되지 않는다. 최종 코드로 저장 흐름을 다시 검증한다.

## 연결 설정과 검증

사용자 승인 후 기존 키의 Decisions Write 권한만 추가했다. 같은 운영 Secret Manager 키와 UI의 masked suffix 일치를 내부적으로 확인했다. 권한 화면이 저장돼 있어도 프로젝트를 생략하면 403이 발생했고 `OpenAI-Project`를 명시한 동일 키 요청은 200이었다. 서버 양쪽 API에 명시적 프로젝트 설정을 전달한다. 비밀이 아닌 `OPENAI_PROJECT_ID`는 git에서 제외된 `functions/.env.onnuriway`에 저장했다. 다른 키 권한·키 값·결제 설정은 변경하지 않았다.

관련 단위 148개, 루트·Functions 타입 검사, 관련 ESLint, Functions build를 통과했다. 기존 38개와 신규 14개를 합친 저장 흐름 52개, 실제 최종 API 결과 5건의 에뮬레이터 재생도 모두 통과했다. 독립 검토의 네트워크 실패 집계 누락과 invoice 별칭 충돌 문제를 수정하고 회귀 검사를 추가했다.

기존 호출·App Check·직원 권한·revision·request ID·감사 이력·서버 확인 후 완료 조건을 유지했다. 실제 API 결과를 데모 Firestore에만 재생하며 운영 쓰기는 0건이다. 운영 Hosting build·배포, 설치형 휴대폰과 현장망 시험은 수행하지 않았다. 배포 시 이전 미배포 일괄 등록 기능과 함께 서버·Hosting을 맞춰 배포해야 한다.

현재 구성은 글자 인식과 정확한 등록명 연결을 개선하지만 처리 시간과 API 입력량이 증가한다. Decisions가 모호한 줄임말 확인을 줄인다는 효과는 이 사진에서 입증되지 않았다. 추가 실사진으로 검증하기 전 자동 연결 기준을 낮추지 않는다.
