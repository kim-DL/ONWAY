# 사진 인식 모델 비용·속도 비교와 Decisions 제거

> 후속 상태: 사용자 승인 후 2026-11-08 13:31 KST 운영 배포 완료. 아래는 구현 당시의 실험 기록이며, 최종 검증·배포·데이터 보존은 [릴리스 기록](releases/2026-11-08-photo-batch-sol-luna.md)을 따른다.

2026-11-08. 로컬 구현·실제 API 시험 완료, 운영 배포 없음. 기존 운영 재고·입출고·납품 기록에 시험 쓰기를 하지 않았다. [직전 Decisions 비교](photo-decisions-comparison-20261108.md)를 대체하는 현재 구현 기록이다.

## 최종 구성

- 사진 일괄 인식 기본 모델은 `gpt-6.1-sol`, reasoning `low`다. 손글씨·인쇄 거래처 목록은 Responses 한 번으로 처리한다.
- 첫 결과가 명세서이면 동일 사진을 `gpt-6-luna`로 한 번 더 읽는다. 실제 명세서에서 Luna가 더 정확했기 때문이다. 최종 이름·주소·날짜는 Luna의 완전한 결과를 사용하며 첫 결과와 섞지 않는다. 종류나 명세서 수가 다르거나 두 번째 호출이 실패하면 자동 저장하지 않는다. 두 모델 설정이 같으면 중복 호출을 생략한다.
- 기존 단일 명세서 API는 Luna를 그대로 사용한다. 모델 설정은 기존 `PHOTO_OPENAI_MODEL`, `INVOICE_OPENAI_MODEL`을 따른다. Astra로 자동 전환하지 않는다.
- Decisions 호출·후보 재판단·이름 좌표 출력·잘라낸 이미지 처리와 그 단계만을 위한 중간 Firestore 읽기를 제거했다. 인식 뒤 최종 권한 검증 트랜잭션에서 최신 거래처와 줄임말을 읽어 연결한다.
- 쉼표·세미콜론으로 병기한 등록 상호의 유일한 정확 일치는 유지한다. 공백만으로 이름을 임의 분리하지 않으며 괄호 지점명은 보존한다. 다른 거래처의 정식 상호를 줄임말로 덮어쓸 수 없다.
- 날짜·주소·불확실성·권한·revision·request ID·감사 이력·원자적 목록 병합·서버 확인 계약과 직원별 수동 확인 후 줄임말 기억을 유지했다. 사진은 RAM에서만 전달하고 Firebase에 저장하지 않는다.
- 키 권한·비밀 정보는 이번 작업에서 변경하지 않았다. 이전에 승인한 Decisions Write 권한은 그대로이며 런타임 호출만 제거했다.

## 손글씨 동일 사진 비교

첨부 손글씨 사진 1장, 12줄, 같은 전처리·프롬프트·등록 거래처 snapshot 223곳·빈 줄임말을 사용했다. 각 구성 5회, 순서를 번갈아 직렬 실행했다. 정답은 평가에만 사용하며 모델에 전달하지 않았다. `승`과 `용`의 사용자 정정도 평가에만 반영했다.

| 구성 | 정확히 읽힌 이름/기대 이름 | 자동 연결/장 | 누락 | 시간 중앙값 | 범위 |
| --- | --- | --- | --- | --- | --- |
| 직전 Astra + Decisions | 55/60 | 5 | 없음 | 13.58초 | 11.22~15.73초 |
| Astra, Decisions 제거 | 55/60 | 5 | 없음 | 9.05초 | 7.19~9.43초 |
| **Sol 6.1, Decisions 제거** | **55/60** | **5** | **없음** | **4.74초** | **3.89~5.10초** |
| Terra 6.1 | 55/60 | 4~5 | 5회 중 2회 한 줄 누락 | 6.32초 | 6.21~7.18초 |
| Luna 6 | 49/60 | 4~5 | 없음 | 6.19초 | 5.63~7.83초 |
| GPT-5 nano | 14/60 | 성공한 분석에서 0~2 | 성공한 3회 모두 3줄 누락; 2회 결과 검증 실패 | 성공한 3회 5.94초 | 5.77~6.36초 |

정확도는 글자 단위가 아닌 이름 전체의 정확 일치다. 행이 누락된 경우 순서 정렬을 통해 뒤의 정상 이름까지 오류로 계산하는 것을 막았으며, 누락 자체는 오답으로 포함했다. Nano의 결과 검증 실패 2회도 성공으로 계산하지 않았다. 원시 비교 파일의 인덱스 기준 통계 대신 `summary.json`의 정렬된 평가를 최종 수치로 쓴다.

Sol은 자동 연결 25건 모두 평가 대상과 일치했고, 다른 성공한 구성에서도 잘못된 자동 연결은 발견되지 않았다. Sol 자동 연결은 매번 더푸드·나누리·자연유통·금필·이레 5곳이다. `승`을 `송`으로 읽는 문제는 남아 있으며 확인 대상으로 유지한다. 등록 snapshot에 `용푸드`라는 정식 상호가 없어 그 대상 ID는 추측하지 않았다.

Sol은 직전 구성보다 중앙값 약 65% 단축, Astra 단독보다 약 48% 단축됐다. 반복 사진의 캐시가 적용된 로컬→OpenAI→로컬 시간이며 실제 휴대폰 업로드·운영 Functions 시작·Firestore 저장까지 포함한 시간이 아니다. 한 사진을 반복한 결과이므로 다른 필체·촬영 조건의 일반 정확도는 아니다.

## 실제 명세서 별도 확인

원래 첨부한 명세서 사진을 같은 전처리로 각 모델 5회 비교했다. 별도 탐색 1회에서 Sol이 `소온푸드`로 읽어 추가 비교를 시작했으며, 그 탐색 결과는 다음 5회 통계와 섞지 않았다.

| 단독 모델 | 소은푸드(금산) 정확 인식 | 같은 날짜로 대조했을 때 주소까지 연결 |
| --- | --- | --- |
| Sol 6.1 | 1/5 | 1/5 |
| Astra | 2/5 | 2/5 |
| Luna 6 | 5/5 | 5/5 |

비싼 모델이 이 명세서를 더 잘 읽지 않았다. 이 결과를 바탕으로 명세서만 Luna로 다시 읽는 위 구성을 구현했다. 최종 실제 API 경로 5회 모두 상호·주소 연결과 거래일자 인식이 맞았다. 중앙값 4.90초, 범위 4.56~5.52초, 사진당 Responses 2회다.

명세서의 11월 9일과 시험일 11월 8일이 다르므로 오늘 자동 등록은 차단되고 날짜 확인을 요구한다. 같은 날짜 자동 연결은 평가용 날짜와 에뮬레이터에서만 확인했다. 운영 오늘 목록에 시험 등록하지 않았다.

## 비용

[OpenAI 공식 요금표](https://developers.openai.com/api/docs/pricing), 2026-11-08 Standard·짧은 문맥 기준. [공식 모델 목록](https://developers.openai.com/api/docs/models)의 실제 모델 이름은 GPT-6.1 Sol, GPT-6.1 Terra, GPT-6 Luna다.

| 모델 | 입력/출력 100만 토큰 USD | 이번 손글씨 1,000장 추정 USD |
| --- | --- | --- |
| Astra | 10 / 50 | 53.75 |
| Sol 6.1 | 2 / 10 | 10.59 |
| Terra 6.1 | 1 / 5 | 5.40 |
| Luna 6 | 0.10 / 0.50 | 0.63 |
| GPT-5 nano | 0.05 / 0.40 | 성공 응답 기준 0.66, 실패 요청 비용 별도 |

1,000장 열은 이번 실제 입력·출력 토큰 중앙값에 할인 없는 기본 단가를 적용했다. 같은 사진 반복에 따른 캐시 할인은 미래 사진 비용 추정에 사용하지 않았다. 30분 신규 캐시 쓰기 요율까지 보수적으로 적용하면 Sol 손글씨는 약 $0.01225/장, 최종 명세서 구성은 두 호출 합계 약 $0.00941/장이다. 실제 청구서가 아닌 토큰 기반 추정이며 세금·환율·다른 API·Firebase 비용은 포함하지 않는다.

직원 2~5명이 22근무일 동안 하루 목록 사진 한 장씩 분석하면 월 44~110장, 약 $0.54~$1.35다. 월 $100를 이 기능에만 쓰는 가정에서는 이번 손글씨 크기 기준 약 8천 장 분량이다. 납품 증빙 사진 저장 전체를 API 인식 건수로 계산한 것이 아니다. 명세서를 15~20장 따로 찍으면 촬영 장수만큼 요청이 늘어난다.

## 검증과 증거

- 관련 단위 테스트 79개 통과. 목록 1호출·명세서 Luna 재판독·분류/장수 불일치·동일 모델 중복 방지·두 번째 API 실패 시 저장 방지를 포함한다.
- 기존 경로·명세서 서비스 에뮬레이터 19개, 사진 일괄·줄임말 에뮬레이터 20개 통과. 등록 상호를 다른 거래처 줄임말로 저장하지 못하는 회귀도 유지했다.
- 실제 Sol 손글씨 결과 5개, 최종 명세서 결과 5개를 서로 다른 두 날짜로 재사용한 서비스 검사 10개, 합계 15개 통과. 같은 요청 재전송 시 인식 재호출 없음과 내 목록/오늘 목록 저장을 확인했다.
- root/Functions 타입 검사, 변경 범위 ESLint, Functions build, diff 공백 검사 통과. UI 변경이 없어 Hosting 빌드와 브라우저 전체 검사는 반복하지 않았다.
- SDK가 로컬 에뮬레이터에서 자격 증명 메타데이터 탐색 경고를 냈으나 demo 프로젝트·로컬 주소 검사로 제한했고 테스트는 성공했다. 운영 데이터 쓰기·배포 없음.

Git에서 제외된 `output/photo-response-optimization/`에 `comparison.json`, 정렬 평가 `summary.json`, 명세서 단독 `invoice.json`, 최종 `invoice-final.json`, `actual-emulator-result.json`과 재현 스크립트가 있다. 비교 시작 시 소스와 이미지 해시를 기록했다. 최종 변경은 기본 모델 및 명세서 분기이며 손글씨 호출 구성은 측정과 같다. 비교에 쓰인 이전 Decisions 소스는 같은 폴더의 `before/`에만 보존했다.
