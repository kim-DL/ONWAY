# Phase 18 Pilot 실행서

## 현재 상태

`PREPARED · STAGING DEPLOYED · PILOT NOT STARTED`

자동화와 운영 양식, HTTPS Staging([onnuriway.vercel.app](https://onnuriway.vercel.app)), 전용 Firebase Project와 보호된 Functions 배포는 준비됐다. 실제 직원 참여, 비식별 데이터·계정 준비, 개인정보 안내와 책임자 승인은 아직 완료되지 않았다. 이 조건 없이 Pilot을 시작하거나 Production을 승인하지 않는다.

## 목적과 범위

급식길 릴리스 후보를 실제 업무 환경에서 72시간 이상 14일 이하로 사용하며, 자동화가 대신 판단할 수 없는 발견 가능성·정보 정확성·입력 부담·체감 성능을 확인한다.

- 납품 직원 1~2명
- 홍보 직원 1~2명
- 관리자 1명
- 실명·이메일 대신 `PILOT-DEL-01`, `PILOT-SAL-01`, `PILOT-ADM-01` 형식의 참여자 코드를 기록한다.
- Production이 아닌 HTTPS Staging과 별도 Firebase Project를 사용한다.
- 학교 데이터는 승인된 비식별·정제본만 사용한다.

## 시작 전 Gate

1. `npm run test:acceptance`가 현재 후보 코드에서 `passed`, P0 0, P1 0 리포트를 생성해야 한다.
2. `pilot/phase-18-plan.example.json`을 `pilot/phase-18-plan.local.json`으로 복사하고 실제 Staging·기간·참여자 코드를 입력한다.
3. 개인정보 안내와 Pilot 책임자 승인을 받은 뒤 두 승인 값을 `true`로 바꾼다.
4. `npm run pilot:readiness`가 `ready`여야 한다.
5. 관리자가 비상 연락 채널, Maintenance Mode, 계정 비활성화, 세션 폐기 절차를 실제 Staging에서 확인한다.
6. GitHub 후보 Commit, Vercel Staging Deployment, `docs/phase-18-status.md`의 검증 기록이 같은 후보를 가리키는지 확인한다.

Local 계획 파일과 생성 결과는 Git에 커밋하지 않는다. 참여자의 이름, PIN, 전화번호, 이메일, 학교 방문 내용은 Pilot 문서에 기록하지 않는다.

## Day 0

- 설치 링크와 PIN을 개별 전달한다. PIN은 문서나 단체 채널에 기록하지 않는다.
- 데이터 수집 범위가 설문 응답과 개인정보 없는 기기 진단임을 설명한다.
- UI 사용법은 가르치지 않고 지원·중단 요청 방법만 안내한다.
- 각 참여자는 로그인, 앱 종료·재실행, 명시적 로그아웃을 한 번 확인한다.

## 무안내 UX 과제

관찰자는 경로나 버튼을 알려주지 않는다. 막힌 지점, 첫 성공까지 걸린 시간, 도움 요청 여부만 참여자 코드로 기록한다.

### 납품

1. 둔산초를 찾아 검수시간을 확인한다.
2. 학교 사진을 열고 확대한다.
3. 네트워크를 끊은 뒤 앞서 본 학교의 핵심 정보를 다시 확인한다.

### 홍보

1. 내 구역과 전체 보기의 차이를 확인한다.
2. 오늘 방문 기록에 홍보지·샘플·하트 관심도·후속 활동을 남긴다.
3. 다른 직원 기록을 조회하되 수정할 수 없는지 확인한다.

### 관리자

1. 직원 활성 상태와 역할을 조회한다.
2. 월 Cycle과 배정을 확인한다.
3. Audit, Maintenance Mode, 세션 폐기와 Pilot 중단 절차를 확인한다.

## 매일 관찰

- 학교 검색 속도와 초성 검색 발견성
- 사진의 현장 유용성, 확대 방식, 불필요한 Original 다운로드 여부
- 검수시간·대차·연락 정보의 정확성
- 내 구역/전체 보기 구분과 팀 조회 경계
- 방문 기록·홍보지·샘플·후속 입력 부담
- 하트 관심도의 의미
- 로그인 유지와 사용자 전환 격리
- 느린 네트워크·Offline 조회·재연결 복구
- 버튼 최소 44×44px 체감과 오동작
- 발열, 배터리, 멈춤, 화면 흔들림

느림이나 멈춤이 발생한 직후 설정의 `Pilot 기기 진단 → 진단 내보내기`를 사용한다. 파일에는 앱 버전, 시간, 온라인/설치 상태, 집계 성능·캐시·읽기 횟수만 들어가며 직원·학교·검색어는 포함하지 않는다.

## 결함 분류와 중단

| 등급 | 정의 | 조치 |
| --- | --- | --- |
| P0 | 업무 차단, 권한 우회, 데이터 유실, 로그인 불가, Crash | 즉시 Pilot 중단, Maintenance Mode 또는 계정 폐기, 수정 후 Phase 17 재실행 |
| 핵심 P1 | 반복되는 핵심 업무 불편, 잘못된 정보, Offline 실패 | Production 전 수정, 영향 경로와 전체 회귀 재검증 |
| P2 | 취향 또는 미세 디자인 | 근거와 빈도를 남기고 v1.1 후보로 분리 |

권한 우회, PIN/Secret 노출, 잘못된 사용자 데이터가 보이면 다른 경로를 계속 시험하지 않고 즉시 중단한다.

## Pilot PASS

- 모든 참여자가 72시간 이상 참여하고 역할별 무안내 과제를 한 번 이상 완료
- P0 0, 핵심 P1 0
- 납품의 홍보정보 접근 차단과 팀 조회 전용 경계 확인
- 로그인 유지·로그아웃·사용자 전환 격리 확인
- 검색, 사진, 현장정보, 방문 기록, Offline 핵심 조회 확인
- 기기별 느린 네트워크와 버튼 크기 확인
- 피드백 질문 전부 회수
- 관리자 종료 검토와 명시적 Production 승인

하나라도 충족하지 않으면 `Pilot PASS`가 아니며 Production 배포를 시작하지 않는다.
