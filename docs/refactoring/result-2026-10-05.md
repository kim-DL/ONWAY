## 이번 범위에서 남기는 제한

- 구현 검증 단계에서는 안전 설정·demo export를 사용했다. 후속 릴리스는 위 기록처럼 기존 배포 PC의 실제 운영 설정으로 새 후보를 만들어 `verify:hosting:build`까지 통과한 뒤 배포했다. 클라우드 안전 설정·demo export는 계속 운영 배포 대상으로 사용하지 않는다.
- 의존성·lockfile·Firestore/Storage Rules·DB schema·사진 보관/lease 정책은 바꾸지 않았다. 이번 구조 정리에 migration/backfill은 없다.
- audit의 moderate 8 / high 0 / critical 0 중 신규 `ip-address`는 Firebase CLI의 개발 의존 경로다. 구조 변경과 의존성 수정의 원인 분리를 위해 이번에 업그레이드하지 않으며, 기존 7건의 기한부 예외에 자동 편입하지 않는다. production 도달성 미발견은 취약성 부재의 증명이 아니다. 별도 의존성 보안 작업으로 남긴다.
- 현장정보/영업의 transaction 내부 세션 재확인 차이, 사진 공통화, 인증 state machine과 receipt engine 재설계는 [계획의 후순위 항목](../superpowers/plans/2026-10-05-onnuriway-refactoring.md)에 남긴다. 새 보안 정책을 동작 보존 변경으로 위장해 적용하지 않는다.
- 실제 iPhone/Galaxy 현장망·설치 PWA 검증은 이번 자동 브라우저 결과와 구분한다.
