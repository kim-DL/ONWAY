# 납품사진 이후 경로 재추천과 출발·도착 선택

납품사진이 이미 있는 날에도 오늘 납품 순서를 추천할 수 있다. 기존에는 회사 전체의 당일 사진 한 장만 있어도 서버가 경로 계산을 차단했다. 이 차단을 제거하고 오늘 전체 거래처 집합을 유지한 채 순서만 추천·적용한다. 사진과 기록완료 판단, 남은 납품처 필터는 기존대로 유지한다.

출발지는 회사 또는 오늘 거래처 중에서 선택하고 마지막 납품처를 고정한다. 거래처 출발은 그 거래처의 등록 주소부터 계산하며 회사에서 첫 거래처까지 구간은 포함하지 않는다. 첫·마지막이 같으면 계산하지 않는다. 주소는 화면과 같은 등록 주소 우선순위로 해석한다. 선택과 추천 버튼을 현재 목록보다 먼저 표시해 모바일에서 바로 조작할 수 있게 했다.

회사 출발 입력과 공개 응답 형식은 유지했다. 권한·날짜·revision·주소 및 오늘 목록 재검증, request ID, 적용 receipt와 감사 이력을 유지한다. 추천 성공 뒤 기존 apply Callable로 오늘 순서를 저장하고 서버 확인 후 완료 표시한다. 저장 응답 유실은 같은 request ID로 저장만 재시도한다.

첫·마지막 두 거래처만 선택한 경우 경유지 최적화 API가 빈 경유지를 받지 않는 것을 실제 요청으로 확인했다. 이 경우 처음부터 화물차 단일 경로 API를 한 번 사용한다. 다른 경우에는 기존 경유지 최적화를 사용한다. 기존 냉동탑차 제원과 제한 안내를 유지한다.

## 로컬·실제 제공자 검증

- 수정 전 다른 직원의 납품사진으로 같은 오류를 demo Firestore에서 재현했다.
- 관련 단위·Callable·주소 시험 42개, 기존 Firestore gate 19개와 신규 재추천 통합 7개 통과.
- 모바일·PC Chromium E2E 30개 통과. 회사/거래처 출발, 동일 양 끝 차단, 선택 변경, 긴 이름 320px, 저장 응답 유실, 수동 순서 편집을 포함한다.
- 전체 typecheck·lint, Functions build와 변경 시험 strict TypeScript 통과. 독립 검토 SAFE.
- 실제 후보 제공자의 회사 출발+경유지, 거래처 출발 두 곳, 거래처 출발+중간 경유지 세 요청 모두 HTTP 200과 순서·거리·시간 파싱을 확인했다. Firebase 업무 시험 쓰기 0건이다.
- 실제 화면 320px·390px 캡처에서 가로 넘침과 페이지 오류가 없었다. 실물 휴대폰·설치 PWA·실주행은 이 검증에 포함하지 않는다.
- 첫 운영 빌드에서 명세서·경로 화면 JavaScript gzip이 8,263B가 되어 기존 8,192B 한도를 71B 초과했다. 회사 설정 지연 로딩과 목록 helper 실험은 각각 공유 청크 배치 영향과 크기 증가로 채택하지 않았다. 한도와 기존 지연 로딩 경계를 유지하며 초기/재조회 Promise 처리, 행 집계와 선택 렌더링을 공유하고 쓰지 않는 파일명 상태를 제거했다. 안내 문구는 사진 미보관·기저장 목록 보존·선택 한도·재시도 방법을 유지하며 줄였다. 비동기 처리의 첫 정리안은 lint가 거절해 기존 Promise callback 방식으로 정리했고 규칙을 비활성화하지 않았다. 실패 로그를 보존하고 최종 후보의 설정 진입·저장 E2E와 빌드 및 세 gate를 다시 확인한다.
- 격리 worktree의 `node_modules` Junction 환경에서는 수정하지 않은 영업 화면도 gzip 14,338B로 14,336B 한도를 2B 넘었다. 기존 일반 작업공간의 같은 영업 코드 빌드는 14,333B였다. 실제 청크 ID와 압축 결과 차이를 기록했고, 영업 코드나 검사 한도를 바꾸는 대신 정확한 후보 소스를 원래 의존성 배치에서도 빌드해 확인한다. 서버 배포는 기존 환경 6개를 보존한 격리 worktree에서, Hosting은 정상 의존성 배치의 검증한 출고 파일에서 수행한다.

## 릴리스 범위

사용자가 최종 점검 후 배포를 명시적으로 승인했다. 대상은 `recommendDeliveryRoute`, `applyDeliveryRoute`와 `hosting:onnuriway`다. MCP 서버, 다른 Functions, Rules, Auth, Storage와 업무 데이터는 배포하지 않는다. 배포 전후 기존 업무 문서와 줄임말 해시를 비교한다.

정확한 후보 CI, 운영 build/PWA/성능/Hosting 검사, 배포·공개 주소·런타임 및 데이터 대조 결과는 완료 후 이 기록에 추가한다. 원시 증거는 기본 작업공간의 git 제외 `output/route-replanning/`에 보관한다.
