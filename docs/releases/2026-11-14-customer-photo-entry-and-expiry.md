# 거래처 사진 기록 연결과 재고 임박 표시

2026-11-14 사용자가 거래처 상세의 사진 기록 연결 개선과 재고 유통기한 임박의 붉은색 표시를 함께 커밋하고 운영 배포하도록 요청했다. 이번 배포 범위는 `onnuriway`의 앱 Hosting이다.

## 반영 내용

- 거래처 상세에 기록 조회와 `납품사진 기록하기`를 묶은 카드, 전용 SVG, 제목16px·설명14px와 등록 날짜를 적용한다. 해당 거래처가 선택된 기존 촬영·앨범 화면과 상세 복귀를 연결한다.
- 재고 목록의 임박 문구와 상세의 임박 배지 글자를 `#b83244`로 통일한다. 상세 배지 배경은 연한 붉은색 `#fff0f2`이다. 날짜 기준, 재고 수량과 실사 상태의 색은 변경하지 않는다.
- 서버·인증·권한·업로드 보관과 복구 계약을 유지하며 업무 목록을 자동 저장하지 않는다.

## 배포 전 확인

사진 연결의 단위71개·브라우저56개, 재고 관련 단위60개와 타입/관련 lint가 통과했다. 독립 소스 검토에서 찾은 닫은 상세의 재표시는 브라우저에서 재현해 수정했다. [구현·로컬 검증 기록](../customer-detail-photo-entry-20261114.md)에 범위와 실패 이력을 남겼다.

Aside의 운영 연결 없는 합성 화면에서 목록과 상세의 임박 표시를 확인했다. 두 곳의 글자색은 `rgb(184, 50, 68)`, 상세 배경은 `rgb(255, 240, 242)`였다. 전체 CI, 운영 형식 빌드와 artifact gate, 배포 전후 검증은 고정한 최종 후보에서 수행했다.

첫 운영 형식 빌드와 PWA/Hosting 검사는 통과했지만 CSS 검사에서 실패했다. 새 상세 카드의 지연 로딩 경계가 검사 registry에 없어 공용 CSS로 집계됐고, 촬영 대상 UI도 기존 사진 workspace의 CSS/JS 한도를 넘겼다. 기존 한도를 유지하면서 대상 UI를 요청 고객이 있을 때만 로드하는 `delivery-photo-capture-entry`로 분리했다. 새 상세 카드와 촬영 대상 경계에는 기존 registry 방식의 별도 작은 한도를 등록했다. 기존 초기·공용·사진 workspace 한도는 바꾸지 않았다. 후속 운영 빌드와 성능 artifact 검사는 통과했다. 첫 후보의 CI는 이 변경으로 대체되어 취소했다.

후속 CI의 납품사진 통합 검사 16개 중 1개는 기존 `/납품사진 기록/` 선택자가 새 `기록하기` 버튼도 함께 찾아 실패했다. 로그의 두 버튼과 실제 컴포넌트를 대조한 뒤 조회 버튼의 구분 문자를 선택자에 포함하고 새 기록 버튼의 활성 상태도 별도로 검사하도록 수정했다. 나머지 고객 범위·네트워크·조회 기대값은 유지했다. 이 후보의 결과를 최종 성공으로 집계하지 않는다.
