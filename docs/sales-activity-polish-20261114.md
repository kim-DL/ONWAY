# 영업 활동 탭과 빈 목록 디자인

## 변경

방문 전·후속 관리·완료를 배경과 테두리 없는 이동 밑줄 탭으로 통일했다. 홈의 두 칸과 활동의 세 칸이 같은 CSS 규칙을 사용하며 기존 선택 상태와 필터링은 유지한다. 빈 목록의 초록 체크는 펄 화이트 세라믹 목록으로 교체했다. 담당 학교 추가는 기존 학교 화면 연결을 유지하고 펄 바탕·얇은 경계·세라믹 더하기로 표시한다. 기존 공개 아이콘을 재사용하므로 새 이미지 생성이나 사전 캐시 경로 변경은 없다.

기존 상태형 Queue와 QUEUES 배열은 그대로다. 새 상태나 공통 React 구성요소를 추가하지 않았다. Poteto의 Model the Domain과 Laziness Protocol에 따라 기존 상태를 사용하고 이미 적용된 밑줄 규칙을 공유했다. 독립 검토에서 320px·200% 글자의 과도한 줄바꿈 가능성을 지적해 탭의 좌우 여백을 8px로 줄였다.

## 검증

첫 관련 브라우저 6개 중 4개 통과, 2개는 고대비 모드에서 투명색이 `rgba(255, 255, 255, 0)`로 반환되는데 `rgba(0, 0, 0, 0)`만 기대한 테스트 오류였다. 색상 성분 대신 alpha 0을 검사하도록 수정했다. 패딩 보완의 영향을 받는 홈 범위·활동 전환 4개만 재실행해 모두 통과했다. 빈 목록·아이콘 decode·담당 학교 추가 이동 2개는 첫 실행에 통과했다.

세 상태의 실제 목록, 선택 밑줄 위치와 투명 배경, 키보드, 200% 글자 확대, 강제 색상, 접근성과 44px 버튼을 확인했다. 변경 TSX·테스트 ESLint, diff 검사, 최종 운영 빌드 및 성능·PWA·Hosting 산출물 검사가 통과했다. 전체 CI는 사용자의 중복 검사 금지 지시에 따라 반복하지 않았다.

Aside에서 활동 빈 목록과 컨트롤 구성을 확인했다. 화면 캡처는 CDP 시간 초과로 실패했으며, Playwright가 저장한 실제 합성 화면 `output/sales-activity/empty-mobile-chromium.png`로 시각 검토했다. 이 캡처는 200% 탭 여백 보완 이전이며, 이후 탭 변경은 관련 브라우저 검사로 확인했다. 미리보기 탭과 서버를 종료했다. 실물 휴대폰·설치 PWA·인증된 운영 쓰기는 검증하지 않았다.
