# 영업 모드 목록과 방문 기록 가독성 개편

기준 소스는 `dfb6863`이다. 영업 직원이 학교명, 담당자, 전달 상태와 방문 내용을 쉽게 읽도록 한다. 재고 모드처럼 이어지는 목록을 사용하고 기존 새벽 배경, 유리 내비게이션, 세라믹 빠른 작업을 유지한다.

## 화면 방향과 선택

- 제품은 영업 직원의 담당 학교, 방문과 후속 업무를 관리하는 급식길이다.
- 성격은 차분함과 명확함이다. 작은 글자를 크게 만들고 정보의 중요도를 나눈다.
- 기존 펄 표면과 옅은 새벽 배경을 유지한다.
- 유리 내비게이션과 세라믹 빠른 작업에 재질 표현을 모은다. 각 정보 행에는 그림자를 반복하지 않는다.
- 학교 범위와 활동 상태의 이동 밑줄을 유지한다. 학교급 아이콘은 모양으로 구분한다.

독립된 같은 모델의 두 설계를 비교했다. A는 하나의 목록 면과 구분선이고, B는 개별 가로 행 카드와 상태 열이다. 별도 설계 검토도 A를 선택했다. 카드 절제와 재고 목록 요청에 맞는 A를 기반으로 B의 18px 학교명, 16px 주요 정보와 상세 내부 카드 축소를 적용했다.

`SalesAssignment`, `School`, 담당자 이름과 동선 순위가 기존 행의 입력이다. 새 저장소나 UI 상태를 추가하지 않고 `AssignmentCard`와 `ActivityRow`의 버튼, 체크박스와 콜백을 유지한다. Model the Domain은 기존 배정과 학교 입력을 유지하도록 했고, Laziness Protocol은 새 목록 추상화 없이 기존 wrapper와 스타일을 정리하도록 했다. Prove It Works는 실제 컴포넌트와 브라우저의 최종 글자 크기, 줄바꿈과 터치 동작을 검증하도록 했다.

## 실제 변경

학교 목록을 한 열의 통합 목록으로 바꿨다. 개별 행의 둥근 테두리, 그림자와 hover 이동을 없애고 구분선으로 나눈다. 학교명은18px, 지역·담당·전달 상태와 업무 상태는16px, 최근 방문과 제한 사유는14px이다. 긴 학교명과 담당자는 줄 수를 제한하지 않는다. 선택과 disabled 이유, 기록된 미전달 및 미확인, 최근 방문과 동선 순위는 계속 표시한다.

초등학교는 책, 중학교는 학교 건물, 고등학교는 학사모 SVG로 구분한다. 기존 `SchoolTypeMark`를 재사용하고 영업 목록에서는40px 표식과24px SVG로 키운다. 활동, 학교 상세와 영업 검색도 같은 학교급을 전달한다. 납품 학교 모드의 세라믹 검색 이미지는 유지한다.

이번 달 요약 안의 작은 지표 카드를 줄이고 중앙 정렬된 숫자와 라벨로 구분한다. 학교 상세의 관심도, 다음 행동, 연락처와 협업 정보도 내부 판을 줄이고 여백과 구분선으로 읽게 한다. 이름, 전화번호와 다음 행동은16px이다.

사용자가 추가로 지적한 방문 이력을 우선 보완했다. 제목은 '방문 기록'으로 정리했다. 날짜는18px, 담당·방문자와 전달 상태, 전달 샘플과 대화 본문은16px이다. 본문 줄간격은1.7이고 줄바꿈을 보존한다. 기록마다 있던 카드 테두리와 상태 pill을 줄이고 연속된 타임라인으로 정리했다. 기록 상태와 수정 권한, 샘플·활동 태그, 후속 일정은 유지한다. 배정 월은 방문 날짜와 혼동하지 않도록 '월 배정'으로 표시한다.

방문 입력, 담당 학교 가져오기, 동선 선택과 학교 검색의 작은 글자를 확대했다. 주요 필드와 입력은16px, 보조 안내는14px 이상을 사용한다. 모바일 상세와 방문 입력의 두 열을 한 열로 전환하고 글자 확대 시 선택과 하단 저장 버튼이 줄바꿈되도록 했다. 기존 읽기 전용, 저장 실패, 재시도와 취소 보호는 유지한다.

영업에 한정한 선택자로 학교 상세의 상태, 하단 메뉴와 빠른 작업, 연락처 수정과 사진 보조 글자를 보완했다. 전역 기본 폰트, 다른 모드의 재질과 색, 서버 API와 인증 계약은 변경하지 않는다.

## 검증과 실패 이력

관련 브라우저 검사는 고유33개가 최종 통과했다. 학교 행8개, 영업 홈·활동·추가·검색9개, 지역 필터6개, 동선5개, 실제 학교 상세·방문 폼·이력4개와 공유 학교 검색1개이다. 각 개수는 아래 실행 로그로 다시 확인하며, 재검사 횟수를 고유 검사 수에 더하지 않는다.

320·390·430·768·1280px, 긴 학교명과 담당자, 글자200%, 키보드와 포커스, 강제 색상과 모션 감소, 학교급3종, 전달 정보, 관리 제한과 선택, 과거 월 읽기 전용, stale/빈 목록, 저장 버튼과 선택 버튼의 접근을 확인했다. 변경 관련 실제 컴포넌트를 사용한 합성 데이터 검사다. 운영 데이터는 사용하지 않았다.

처음 앱 미리보기 helper는 앞선 운영 개편의 App Check 준비 함수를 mock에서 제공하지 않아 번들링이 실패했다. mock이 기존처럼 네트워크를 차단하면서 해당 export도 제공하도록 보완했다.

첫 영업26개 중24개가 통과했고 두 개는 옛 글자 크기 및 고정 높이 기대값 때문에 실패했다. 새16px과200%32px을 확인하고 높이 상한 대신 내용과 overflow를 확인한다. 기존 16px/200%32px 학교명 기대값도18px/36px으로 바꿨다. 전체 이름과 overflow, 선택 동작 검사는 유지했다.

새 방문 폼 검사에서200% 확대 시 기존10.5rem 버튼 최소 너비 때문에 저장 버튼이 오른쪽으로 벗어났다. 최소 너비를 없애고 줄바꿈을 허용해 해결했다. 새 이력 fixture는 관심도 척도에 없는3을 사용해 실패했고 실제 계약 값60으로 바로잡았다. 이력에서 긴 하트·사람·후속 정보가 확대 시 넘치는 문제도 줄바꿈으로 수정했다. 새 담당 학교 검사에서는 숨겨진 checkbox를 직접 누르려다 타임아웃이 발생해 사용자처럼 보이는 label을 클릭하도록 수정했다.

별도 코드 검토는 기능 회귀를 발견하지 못했고, 늦은 CSS 규칙 때문에 남은12~13px 안내를 찾아 보완했다. 큰 `:is()` 묶음의 우선순위가 학교 상태16px을14px로 낮추던 부분은 배지 선택자를 분리해 수정했다. 사진 읽기·실패 span도 실제 표시 요소에 맞춰14px로 보완했다.

타입 검사와 변경 TypeScript 파일 lint가 통과했다. 첫 빌드는 앱과 PWA·Hosting 검사를 통과했으나 공통 CSS gzip이 기존 한도를49B 넘었다. 옛 카드 격자와 이미 덮어써지는 밀도 규칙을 제거한 두 번째 빌드는 개별 한도를 통과했지만 합산 CSS 한도에서 실패했다. 방문 이력의 새 스타일을 원래 소유 파일로 모은 세 번째 산출물도 합산 한도를83B 넘었다. 실제 합산 대상과 압축값을 확인한 뒤 중복된 옛 담당 선택·disabled·focus·hover 장식을 제거했다. 네 번째 최종 빌드와 성능·PWA·Hosting 검사는 모두 통과했다. 한도는 변경하지 않았다.

최종 공통 CSS는228,269B, gzip45,246B이다. 공용 사진 UI gzip1,971B를 합한47,217B가 기존47,232B 한도를 충족한다. 최초 JS gzip은144,050B이고, 정적 파일145개와 사전 캐시129개를 확인했다. 이것은 산출물 바이트 검사이며 실행 속도 측정은 아니다. Attack the Premise는 작은 CSS 정리만으로 합산 한도를 만족한다는 가정을 다시 확인하도록 했고, Explain the Number는 실제 합산 대상과 정확한 초과량을 기록하도록 했다. 진단 스크립트는 검증의 assertion을 완화하지 않고 합산 직전의 기존 측정값만 출력한다.

전체 회귀, 백엔드 에뮬레이터와 전체 원격 CI는 이번 표시 변경에 반복하지 않았다. 실패나 이후 수정과 직접 관련된 검사만 재실행했다. 본문과 배정 표시 외 데이터 처리 로직을 바꾸지 않아 별도 새 단위 검사는 추가하지 않았다.

Aside에서 실제 합성 미리보기의 학교 범위 전환과 초중고 표시를 확인했다. Aside 캡처는 세션 안에 저장되며 로컬 산출물로 직접 내보내는 경로가 제한돼, 공유할 로컬 캡처는 Playwright로 생성했다. `before-home.png`, `after-list.png`, `history-readable-mobile-chromium.png`는 가상 데이터 화면이다.

## 기록과 운영 반영

세부 후보, 독립 설계 판정, 구현과 코드 검토, 체크리스트, `decisions.tsv`, 명령 로그와 캡처는 ignored `output/sales-readability-20261114/`에 있다. 최종 커밋과 배포 결과는 확인 후 이 절에 기록한다.

사용자는 커밋, main 병합과 운영 배포를 승인했다. 이번 변경은 Hosting 범위이다. 인증 서버와 직원 세션, 운영 PIN과 Google 계정은 변경하지 않는다. 실제 휴대폰과 설치된 운영 PWA에서의 표시, 인증된 운영 저장은 직접 검증하지 않았다.
