# 영업 모드 가독성과 SVG 개선

영업 담당자가 조회 월의 방문 현황과 담당 학교 상태를 읽기 쉽게 다듬는다. 기존 학교 배정, 방문 동선, 담당 제외 조건, 내 학교와 전체 보기, 과거 월 읽기 전용 동작은 유지한다.

## 확인한 문제와 선택

Aside의 실제 React 합성 화면에서 390px 기준 월 상태는 9.76px, 작업 이름은 10.72px, 담당 정보는 12px, 상태는 11px이었다. 새 가독성 검사에서도 이 문제가 재현됐다. 기존 범위 전환과 관리 제한 검사는 통과했다.

`unslop-ui`로 기존 파란색과 유리 화면을 유지하며 가독성을 다듬었다. 주요 작업 아이콘은 사용자 지정에 따라 세라믹 질감을 제거하고 단색 라인 SVG로 정리했다. `poteto-mode`의 독립 설계 두 안과 새 검토자의 비교를 거쳤다. 저장된 설정에 따라 모든 작업자는 부모 모델을 상속했으며 서로 다른 모델 비교는 아니다.

주요 작업은 정적 SVG를 선택했다. 기존 장식 span과 버튼의 업무 처리기를 사용한다. 48px 좌표계, 2px 선, 짙은 청회색을 공통으로 쓰며 그림자와 그라데이션을 제거했다. 좁은 화면의 2열 배치는 세로 공간을 더 쓰는 대신 글자 크기를 확보한다. 샘플 상태에는 물건을 뜻하는 상자 glyph를 쓴다. 담당 학교·후속·재방문·샘플 전달 지표는 제목·숫자·보조 설명을 모두 중앙 정렬한다.

기존 SalesCycle과 배정 데이터 타입을 유지했다. 상태 모델을 새로 만들지 않는다. 후행 영업 스타일에 덮이는 선언을 정리하고 기존 용량 제한을 유지한다.

## 재현 방법

로컬 미리보기는 `SALES_PREVIEW=true`로 `npx tsx scripts/preview-customer-ceramic.ts`를 실행하고 출력 주소의 `/app?mode=sales`를 연다. 예시 데이터만 사용하며 CSP가 운영 연결을 차단한다.

- `npx vitest run src/features/sales-cycle src/features/sales-route --maxWorkers=2`
- `npx playwright test tests/e2e/sales-polish.spec.ts tests/e2e/sales-school-cards.spec.ts tests/e2e/sales-district-filter.spec.ts tests/e2e/sales-route-planner.spec.ts tests/e2e/customer-presentation.spec.ts --workers=2`
- `npm run typecheck`와 `npm run lint`
- `npm run build:hosting`
- `npm run verify:performance:build`, `npm run verify:pwa:build`, `npm run verify:hosting:build`

검증 결과와 운영 버전은 최종 후보 확인 후 아래에 기록한다. 브라우저 합성 화면, 서버 에뮬레이터, 운영 공개 파일 검증과 실물 기기 사용은 구분한다.

## 검증 및 배포 기록

관련 단위 108개가 통과했다. 첫 관련 브라우저 실행에서는 92개가 통과했고, 합성 빌드의 정적 SVG 경로 해석과 활동 행 높이 검사에서 실패했다. SVG 경로는 실제 public URL로 남기도록 합성 빌드를 고쳤다. 14px 글씨와 전체 주소를 유지하며 활동 행의 세로 여백을 줄였다. 검사 상한은 바꾸지 않았다.

후속 브라우저 78개가 통과했다. 최종 제목과 개수 줄바꿈 수정 뒤 영업 전용 12개도 통과했다. 320·390·430·1280px, 200% 글자 확대, 강제 색상, 키보드, 접근성, 월과 범위 전환, 담당 제외 제한, 빈 목록과 저장된 목록 안내, 활동 큐를 확인했다. SVG 5종 decode와 활성 동선의 아이콘 보존은 표현 상태 검사다. 실제 운영 동선 저장을 실행한 검사는 아니다.

독립 검토가 발견한 두 CSS 충돌을 수정했다. 후행 모바일 규칙이 2열을 덮던 문제와 활성 동선의 배경 shorthand가 SVG를 지우던 문제다. 재검토에서 남은 소스 결함은 발견되지 않았다.

전체 lint와 최종 변경 파일 lint, TypeScript를 포함한 운영 빌드, PWA·성능·Hosting 검사가 통과했다. 마지막 보완 빌드의 gzip 기준 초기 JS는 144,012B, 영업 묶음은 14,316B, 기존 CSS와 공용 사진 CSS 합계는 46,895B다. 변경 전 합계는 47,182B였다. SVG 5개 원본 합계는 1,476B다. 기존 제한을 변경하지 않았다. 이 수치는 전송 파일 용량이며 실행 속도 개선 측정은 아니다.

정확한 후보 커밋의 Quality Gate와 운영 배포 결과는 후속 기록에 남긴다. 실물 휴대폰과 설치된 PWA, 인증된 운영 계정의 실제 방문 저장은 이 로컬 검증에 포함하지 않았다.

## 첫 원격 후보에서 발견한 문제

첫 후보 `df1dc5e`의 [Quality Gate 43566249769](https://github.com/kim-DL/ONWAY/actions/runs/43566249769)는 실패했다. 실패한 후보는 배포하지 않았다.

- 업무 인수 검사에서 학교 빈 목록의 이전 문구와 영업 명령의 한 줄 배치를 기대하던 검사를 현행 UI에 맞췄다. 영업 명령은 두 행의 좌표와 44~96px 높이를 검사한다.
- 기존 학교 상세의 사진 버튼이 데스크톱에서 36px로 줄어드는 실제 문제를 찾았다. 동일 구성요소 합성 검사에서도 33.77px로 재현했다. 기존 학교 전용 규칙에 `min-width: 44px`를 추가했다. 1280px와 폭 검사를 추가한 두 브라우저 검사가 통과했다. 원격의 기존 44px 검사는 그대로 유지했다.
- Linux 브라우저의 입자 전체 궤도 검사에서 인사말 교차가 발견됐다. 같은 검사는 Windows에서 통과했다. 소스상 입자의 상향 범위 약 13.4px에 비해 기존 인사말 아래 간격 3.2px와 8.8px가 부족했다. 영업 홈과 활동의 해당 간격을 16px로 확보했다. 공유 애니메이션은 바꾸지 않았다. 이전 제목을 유지한 상태에서도 로컬 궤도 검사 두 개가 통과한 뒤, 합성 제목을 현행 UI와 동기화했다. 환경별 차이가 글꼴 때문이라는 판단은 추론이며 최종 Linux CI로 확인한다.

Aside의 데스크톱 320px 창에서는 기존 공용 `html` 최소 폭 320px와 클래식 스크롤바 때문에 15px의 가로 넘침이 관측됐다. 이번 변경에서 공용 최소 폭 정책은 바꾸지 않았다. 320px 모바일 Chromium 검사와 실물 기기 검증은 서로 구분한다.

보완 후 학교 상세 두 개와 웰컴·영업 전체 62개 검사가 통과했다. 첫 Linux 입자 검사는 두 프로젝트에서 자동 재시도 두 번까지 실패했으며, 최종 후보의 새 실행과 구분한다.

새 SVG의 PWA 사전 캐시 누락을 추가 확인했다. 진행 중이던 후보 c6db19f의 CI 43567724373은 취소했으며 성공이나 실패로 계산하지 않는다. next.config.ts에 공개 SVG 다섯 경로만 추가하고, PWA 및 Hosting 검사에도 같은 명시적 목록을 추가했다. 런타임 캐시 정책과 비공개 응답 범위는 유지했다. 새 빌드의 사전 캐시 항목은 130개다. 격리된 Chromium 컨텍스트를 오프라인으로 전환한 뒤 SVG 다섯 개가 모두 실제 서비스 워커에서 200으로 응답하고 로컬 파일 SHA-256과 일치함을 확인했다. 기존 운영 빌드 검사도 모두 통과했다.

## 최종 시각 보완

사용자 요청에 따라 세라믹 SVG 다섯 개를 단색 라인 아이콘으로 교체하고, 세 지표의 전체 내용을 중앙 정렬했다. 320·390·430·1280px에서 텍스트 정렬뿐 아니라 각 자식 요소의 중심 좌표가 카드 중심과 1px 이내인지 검사했다. 영업 브라우저 12개, 변경 파일 lint, 운영 build·성능·PWA·Hosting 검사와 서비스 워커의 오프라인 SVG 다섯 개 해시 검증이 통과했다. Aside의 390px 실제 합성 화면에서 정렬과 작업 버튼을 확인했다.

직전 후보 c5e53ac의 Quality Gate 43568157688은 필수 14개 작업이 모두 성공했다. 시각 보완 이전 후보이므로 배포하지 않고 새 후보의 CI를 별도로 진행한다.
