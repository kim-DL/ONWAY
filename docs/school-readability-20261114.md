# 학교 모드 정보 가독성 개편

기준 소스는 `44618e9`이다. 학교 납품 직원이 학교명, 검수시간, 위치, 연락처와 사진 안내를 쉽게 읽도록 한다. 사용자는 `poteto-mode`, `unslop-ui`의 적용과 관련 검증 후 커밋, main 병합, 운영 배포를 승인했다.

## 점검과 방향

기존 유리 내비게이션, 세라믹 검색과 학교 아이콘, 푸른 펄 배경을 유지한다. 홈의 최근 학교는 이미 구분선 목록이며 납품 현장정보도 하나의 브리핑 안에서 정보를 나눈다. 이 구조를 재사용하고 글자 크기, 여백과 줄바꿈을 개선한다.

두 독립 조사자가 홈·검색과 상세·편집·사진 경로를 나눠 읽었다. 같은 모델의 별도 조사이며 브라우저 합격과 구분한다. 부모는 Aside의 실제 합성 AppShell과 로컬 캡처에서 기존 학교명16px, 구·학교급14px을 확인했다. 검색의 결과 수와 단축키, 편집 label과 설명, 사진 등록 및 확대 화면에도 작은 글자가 남아 있었다.

제품은 학교 납품의 현장 정보를 읽는 급식길이다. 성격은 차분함과 명확함이다. 기존 재질과 색을 유지하고, 검색 입구와 내비게이션에 재질 표현을 모은다. 검수시간을 먼저 읽고 위치·장비·참고·연락처를 같은 시작선에서 확인하도록 한다.

## 데이터와 적용 원칙

`School`, `SchoolFieldProfile`, `SchoolPhoto`와 기존 컴포넌트를 사용한다. 저장, 권한, request ID, revision, 감사 이력, 사진 보관과 서버 확인 후 완료 계약을 변경하지 않는다. 새로운 상태와 목록 추상화, 별도 카드 컴포넌트는 필요하지 않다.

Model the Domain에 따라 학교와 현장정보의 기존 입력과 구획을 유지한다. Laziness Protocol에 따라 기존 스타일의 최종 선언을 수정하고 중복 선언을 정리한다. Prove It Works에 따라 실제 컴포넌트의 최종 크기, 줄바꿈과 조작을 브라우저에서 확인한다.

처리량 체크포인트는 선행 상태·화면 확인, 독립된 두 읽기 전용 조사, 단일 CSS 구현, 별도 검증과 코드 검토로 나눴다. CSS·브라우저·빌드 산출물의 공유 쓰기는 직렬로 처리한다. API와 컴포넌트 경계를 바꾸는 새 설계는 범위에 포함하지 않는다.

## 검증과 운영 반영

학교 찾기와 최근·검색 학교명은18px, 최근 학교의 구·학교급은16px으로 정리했다. 시간과 주소·상태 설명은14px이다. 학교 상세는 본문·전화번호·동선·장비 값을16px으로 키웠다. 기존 큰 제목과 검수시간을 축소하지 않고 rem과 적절한 굵기를 사용했다. 좁은 화면의 동선은 한 열로 흐른다.

정보 수정의 필드명과 입력은16px, 보조 설명과 저장 오류는14px이다. 사진 제목과 확대 설명은16px, 읽기·오류·작업·빈 사진·등록 안내는14px 이상이다. native 입력과 저장 버튼의 최소 너비를 없애고, 사진 선택과 확대 footer는 필요한 만큼 줄바꿈한다.

학교·영업에서 같은 검색 helper와 필드 폰트를 여러 번 덮어쓰던 선언을 원래 소유 위치로 모았다. 공유하는 영업 위치·사진과 검색에도 같은 보조 가독성 개선이 적용된다. 앱 TypeScript와 상태, 권한 및 저장 코드는 수정하지 않았다.

관련 브라우저 검사는 고유11개가 모두 첫 실행에서 통과했다. 홈·최근 목록·검색과 공유 영업 검색4개, 실제 납품 상세·확대 편집·사진 안내·저장 실패 후 초안·사진 확대 복귀·공유 영업 상세와 위치6개, 오프라인 검색 안내1개이다. 검사는320·390·430·768·1280px, 긴 이름과 현장 메모, 글자200%, 키보드와 포커스, 강제 색상과 모션 감소, 읽기 전용, 미등록 상태와 오류 복구를 포함한다. 합성 데이터의 실제 컴포넌트 검사이며 실제 운영 저장을 뜻하지 않는다.

독립 코드 검토에서는 수정이 필요한 회귀를 발견하지 못했다. 오프라인 카탈로그 배지가200%에서 넘칠 가능성을 제기했으나, 실제 stale 카탈로그 mock을 추가한 집중 검사에서 요약 영역과 배지 경계가 유지됐다. 이 확인 때문에 앱에 추가 변경을 하지 않았다.

타입과 변경 테스트의 lint, 최종 운영 빌드와 성능·PWA·Hosting 검사가 통과했다. 첫 빌드에서는 사진 확대 CSS가6,925B로 기존6,912B 한도를13B 넘었다. 공통 `base.css`의 `button, input { font: inherit; }`와 중복되는 확대 버튼의 선언만 삭제했다. 사진 확대·복귀 검사1개를 다시 통과했고 최종 빌드도 통과했다. 용량 한도와 검사 기준은 변경하지 않았다.

최종 공통 CSS는226,176B, gzip44,961B이고, 공유 사진 UI는6,912B, gzip1,967B이다. 합산 gzip46,928B가 기존47,232B 한도 안에 있다. 최초 JS는 gzip144,051B이다. 정적 파일145개와 사전 캐시129개를 확인했다. 이 값은 파일 크기 검사이며 실행 속도 측정이 아니다.

앱 빌드는2회였다. 첫 용량 실패를 해결한 뒤 산출물이 달라져 최종 산출물 검사를 다시 진행했다. 이미 통과한 전체 회귀와 전체 원격 CI는 반복하지 않았다. CSS 변경과 직접 관련된 사진 검사만 추가 확인했다. 인증·데이터 처리 코드를 바꾸지 않아 별도 백엔드·에뮬레이터 검사는 실행하지 않았다.

구현 커밋은 `cb30343`, main 병합은 `3dc6d04fa3b9dd98fdd48aafb8f6bb55aa4196dd`이다. main을 원격에 동기화한 뒤 다음 명령으로 Hosting만 운영 배포했다. 사용자 요청에 따라 커밋의 `[skip ci]`로 전체 원격 CI 반복을 생략했다.

```text
node node_modules/firebase-tools/lib/bin/firebase.js deploy --project onnuriway --only hosting:onnuriway --non-interactive
```

운영 Hosting은 `457477f2acda01ef`, 공개 시각은 2026-11-14 23:12:10 KST이다. 이전 Hosting은 `73771763e2a38057`이다. 인증 서버와 계정·세션은 변경하지 않았다.

[회사 도메인](https://onnuriway.com)과 [Firebase 도메인](https://onnuriway.web.app)에서 공개 Hosting 검사가 통과했다. 배포 전에 고정한 main 소스와 산출물 목록을 기준으로 두 주소 각각 정적 파일145개의 SHA-256이 전부 일치했다. 배포 로그는 `deploy.log`, 공개 검사 결과는 `public-domain.json`·`public-firebase.json`, 고정 목록과 해시 대조 결과는 `release-artifacts.json`·`public-artifact-hashes.json`에 남겼다. 마지막 기록 정리는 문서 전용 변경이며 앱을 다시 빌드하거나 재배포하지 않는다.

합성 화면과 로그, 두 감사, 독립 검토, 체크리스트와 `decisions.tsv`는 ignored `output/school-readability-20261114/`에 남긴다. 실제 운영 데이터는 시험용으로 생성하거나 수정하지 않는다. 실물폰, 설치된 PWA와 인증된 실제 운영 저장은 별도 증거가 없으면 검증했다고 표현하지 않는다.
